| BD-M01a2-02 | `BodyDesc.rot` | `BodyDesc` gains an optional `rot: [x, y, z, w]` (default identity). | BD-M01a2-03 | Body ids and snapshot | Body ids are the backend's own sequential u32s (never reused) because Rapier's handles are bit-cast f64 values that do not fit `BodyRef.body`. `snapshot()` is the backend's tables (origin, ids and handles, each chunk's `StaticShapeSet`) followed by `World.takeSnapshot()`; `restore()` rebuilds the world with the static `World.restoreSnapshot`. The physics resource is hashed as origin plus body count (transforms are already in the hashed `Transform`/`Velocity` stores) and checkpointed with the Rapier bytes. | Restore-then-rerun reproduces the hash exactly (AC-3), including across the tick-5,000 rebase. |
| BD-M01a2-04 | Heightfield orientation | `StaticShapeSet.heightfield.heights` is row-major by Z (`heights[iz * nx + ix]`) and `at` is the minimum-X, minimum-Z corner; `nx`, `nz` are sample counts. The backend transposes to Rapier's column-major layout and centres the collider. | The spec gives `nx = 65, nz = 65, at = NW corner` but not the sample order. Rapier's rows run along Z and its columns along X (checked with a ramp in `physics.backend.spec.ts`). M02a1's `toStaticShapeSet` must write the same order. |
| BD-M01a2-05 | Prism colliders | A convex footprint becomes one convex hull of its 2n points; a concave one is ear-clipped and each triangle is its own hull. Rings are normalised to counter-clockwise in (x, z) first, so either winding works. | The C08 pack stores rings, not shapes; Rapier needs convex pieces. All arithmetic is `+ - x` and comparisons, so every engine builds the same pieces. |
| BD-M01a2-06 | Floating origin | The followed entity is the `LocalPlayer`-tagged one, or `PhysicsSystemOptions.followKey`. A rebase fires when its horizontal distance (X, Z) from the origin exceeds `rebaseDistanceM` (1,000, in `config/physics.json`) and moves the origin to the entity's position rounded to whole metres, keeping the old Y. Statics are removed with `wakeUp = true` and rebuilt from the kept shape sets. A rebase to the current origin does nothing. | The spec says "more than 1,000 m" without the new origin. Whole metres keep f32 offsets exact near the entity. Waking resting bodies after a rebase costs a few ticks of settling and keeps contacts valid. |
| BD-M01a2-07 | Init retry | `init()` makes one attempt plus three retries (so `attempts === 4` on failure) with delay `baseMs x 2^(n-1) x (0.5 + jitter())`. `sleep` and `jitter` are injected (sim code has no timers or `Math.random`); the worker passes `setTimeout` and `Math.random`, the default is no wait. | AC-4 needs `attempts === 4` for four failures and a resolve on attempt 3 for two. |
| BD-M01a2-08 | One build per session | `loadRapierBuild(build, { exclusive })` refuses a second, different build in the same realm when `exclusive` is set (the worker sets it). Node tests load both builds in one process, so they do not. Each Rapier build is a literal dynamic `import()`, which the bundler splits into `rapier-simd-*.js` and `rapier-deterministic-*.js`. | C02 rule 5: a different build needs a fresh worker (`SimHost.restart`). |
| BD-M01a2-09 | Command channel | Frame signals, `SimControlMessage`s and debug commands are all JSON envelopes `{ v: 1, t, seq, p }` on the command ring (SAB) or `postMessage` (fallback). When several frame signals are waiting, the worker adds their `dtSec` and advances once (same `timeScale` and `paused`), so a stalled worker catches up through the C02 accumulator clamp and counts `droppedSec` instead of replaying every frame. A full command ring drops the message and counts `commandsDropped`; the page never blocks. | C02 rules 1 and 9. The input block is shared memory (SAB) or an `input` envelope sent just before each frame (fallback), so edges behave the same. |
| BD-M01a2-10 | Snapshots | One snapshot per tick, stamped with the number of ticks completed, written to the slot that is neither the latest nor the previous one under a per-slot seqlock; the order word holds (latest, previous) and the f32 `alpha` lives in the global header. The reader copies latest and previous so the pair is always one tick apart, and returns the previous result when the sequence number is odd or changed. The side block (8 KiB, JSON) carries `rk` (renderKey id to asset string) and the physics `origin`. The fallback posts the last two snapshots at every frame end, even when no tick ran, because `alpha` changes. `SnapshotRead.fresh` is false for repeats and torn reads, and `snapshotReuse` counts those. | The 64-byte record has no room for the asset string, so the string table rides in the side block. |
| BD-M01a2-11 | Start-up handshake | The first message to a new worker is `{ v: 1, t: 'init', p: { cfg, boot, transport, sab, qa } }`; the worker answers with a plain `ready` message (also on the event ring) and an `error` message before it rethrows from a timer so the page's `error` listener fires. `SimHostImpl.start` resolves on `ready`; `restart(cfg)` terminates, bumps `restarts` and starts again. | Neither message is in the C02 vocabulary; they are the bootstrap, not the steady-state protocol. `restarts` counts crash recoveries and profile switches alike. |
| BD-M01a2-12 | Crash and stall detection | `SimHostImpl.frame` reports `stalled` when no fresh snapshot arrived for 2,000 ms of `FrameSignal.nowMs`. The timer starts over after a pause or a gap of more than 1,000 ms between frames (page hidden), so a background tab is not a crash. A worker `error` event or `error` message reports `error` once. `bootEngine` shows the banner and restarts. | Spec: "worker `error` event, or no snapshot for 2 s". |
