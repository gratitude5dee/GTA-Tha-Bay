## Items

1. **Licences files.** New `tools/ci/third-party-licenses.ts`, run by root `build` after the Vite build: for every register entry with verdict `REUSE-WITH-ATTRIBUTION` and a `pinnedSha`, it appends to `apps/web/dist/third-party-licenses.txt` a header (name, each item's SPDX id, URL, SHA, and each item's full `third_party/NOTICE` line verbatim: creator, licence URL, "modified" when `modified: true`; DL-523) followed by `third_party/<name>/LICENSE` verbatim (and its Apache `NOTICE` verbatim when present); no vendored entry → no file. The same tool, given a package directory, writes that package's `THIRD_PARTY_LICENSES.txt` for every entry a ported file in it names; `tools/cli`, `packages/mod-sdk` and the kit that `dv init` copies list that file in their `files` (pack) set once they hold a ported file, and each ported file inside the kit or templates carries the full MIT permission text or a pointer to the licences file shipped beside it (DL-507). Unit test `tools/ci/test/third-party-licenses.test.ts` on a fixture tree.
2. **`license:scan` rules for `third_party/`.** `third_party/` is accepted only through these register checks. Fail when a `third_party/<name>/` directory has no `REUSE-WITH-ATTRIBUTION` entry, no `pinnedSha`, no upstream `LICENSE`, or holds a file outside `allowedPaths`; check each `allowedPaths` item, never the entry: its `spdx` must be MIT or Apache-2.0 for `kind: 'code'` and CC-BY-4.0 for `kind: 'data'` (DL-508), and the root `REUSE.toml` annotation for its path must carry that same `spdx`; a `*.subset.json` must have `modified: true` and keys exactly equal to its item's `fields` names; `fields` may not name a name, description, tagline, URL, logo, person or coordinate field, or an address, city, neighbourhood or district, location, OSM id, building id or footprint-link field, or any other geocoded field (DL-523), and each `fields` entry must carry its reviewer `note` (authored upstream, not OSM- or Nominatim-derived). A `kind: 'data'` item whose `third_party/NOTICE` line lacks the licence URL, or lacks "modified" when `modified: true`, fails. When `apps/web/dist` exists, `apps/web/dist/credits.json` must hold the `NOTICE` line of every vendored item that a "Portions from" header or a C07 provenance record's `derived_from` names (DL-507, DL-523). Every source file with a "Portions from `third_party/<name>/<path>`" header must resolve to an entry whose `allowedPaths` holds that path, must carry the upstream copyright line verbatim (as it appears in that `LICENSE`) and an `SPDX-License-Identifier` line, and, when `apps/web/dist` exists, that entry's `LICENSE` text must appear in `apps/web/dist/third-party-licenses.txt`. A package whose `pnpm pack --dry-run` file list holds a "Portions from" file but no `THIRD_PARTY_LICENSES.txt` fails. Cases in `tools/ci/test/license-scan.test.ts` (fixtures for each failure, including a geocoded `fields` name, a data `NOTICE` line without the licence URL or "modified", and a used item missing from `credits.json`, and one clean tree).
3. **Never bundled, never linted as ours.** `third_party/**` goes into the ESLint `globalIgnores` and the root `vitest.config.ts` `exclude`, so vendored `.js` and tests are neither linted nor run. Separately, ESLint `no-restricted-imports` (pattern `**/third_party/**`) applies to every importer except `tools/{map,assets,ci,soul}/**` (ported code is copied, never imported; those tools may read vendored data to write derived `content/` files), so `apps/`, `packages/`, `services/` and the shipped `tools/cli` are covered; `check:bundle` fails when any module id in the build manifest resolves under `third_party/`; `names:lint` skips `third_party/` in its source scan and, when `DV_NAMES_REAL_JSON` is set, runs its real-side matchers over `apps/web/dist` as well (absent → `SKIP names real-side dist: DV_NAMES_REAL_JSON not set`). Test: `tools/ci/test/no-third-party-import.test.ts`.
4. **Subset extraction tool.** New `tools/ci/third-party-subset.ts`, for the operator at vendoring (DL-502 step 3): reads an upstream JSON or CSV file given by path, keeps only the `fields` names of the named `allowedPaths` item, and writes `third_party/<name>/<path>.subset.json` (canonical JSON, rows in upstream order); it refuses a `fields` list that item 2 would fail. Unit test `tools/ci/test/third-party-subset.test.ts` on a fixture with name, URL, coordinate, address, neighbourhood and OSM-id columns: a `fields` list naming any of them is refused.
5. **PR template.** `.github/pull_request_template.md` attestation reads "No upstream example repository (`research/repos-*.md`) was opened, fetched or searched for this change, and no code, data, names, constants or layouts were consulted or copied from any other repository, except files under `third_party/` listed `REUSE-WITH-ATTRIBUTION` in `docs/legal/third-party-reuse.json`." (DL-508, DL-523; it keeps the clean-room attestation of `research/legal-ip-likeness.md` §2.2). This session is the one that edits `.github/` for reuse; the Architect does not (DL-513).

## Acceptance criteria
- AC-1 Given a fixture tree with a vendored `REUSE-WITH-ATTRIBUTION` entry When the licences tool runs Then `third-party-licenses.txt` holds its upstream `LICENSE` verbatim and a fixture package with a ported file gets `THIRD_PARTY_LICENSES.txt`, and on the real tree (no vendored entry) `pnpm build` writes no licences file — proof: `pnpm check:unit -- tools/ci/test/third-party-licenses && pnpm build && pnpm license:scan`
- AC-2 Given the fixture trees When `license:scan` and the subset tool run on each Then every case of items 2 and 4 fails with its rule named and the clean tree passes — proof: `pnpm check:unit -- tools/ci/test/license-scan tools/ci/test/third-party-subset`
- AC-3 Given a source string at a `packages/` path and one at a `tools/cli/` path that import from `third_party/` When the repository ESLint config lints them (`tools/ci/test/no-third-party-import.test.ts`, ESLint API) Then `no-restricted-imports` reports both, a vendored-path `.js` fixture is ignored, and on the real tree lint, `check:bundle` and `names:lint` pass — proof: `pnpm check:unit -- tools/ci/test/no-third-party-import && pnpm lint && pnpm build && pnpm check:bundle && pnpm names:lint`
