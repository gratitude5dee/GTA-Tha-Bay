# 11 — Decision log, Builder decisions (living, dated)

> The one place where Builders record the small, reversible choices a milestone file leaves open (DL-341). Architect decisions stay in `spec/11-decision-log*.md` parts 1–4; Builders never edit those. One row per decision, newest last, ids `BD-001` onward in run order. A row never changes a contract shape: a contract change is a proposal in the milestone report. When this file nears the 6,000-word cap (`tools/ci/spec-files.ts`), the Architect moves the oldest rows to `spec/11-decision-log-builder-2.md` and leaves a pointer here.

> **Earlier rows:** Builder decisions for M00 … M01f, recorded on `claude/build` before this file existed, are in `spec/11-decision-log-builder-2.md` (M00, M00b, M01a1, M00c, M01a2) and `spec/11-decision-log-builder-3.md` (M01d, M01b1, M01c, M01f), ids `BD-M<id>-NN`. When a Builder merges `claude/architect-spec` into a code branch and `spec/11-decision-log.md` conflicts, take the spec side: the code branch's Builder section is already in those two files. New rows go in the table below only.

## Builder decisions

| ID | Milestone | Decision | Why | Reversible by |
|---|---|---|---|---|
| BD-001 | M01e | Playwright WebKit's default context has no OPFS (`navigator.storage.getDirectory()` throws `UnknownError`; observed on webkit-2370, Linux). The `@pack-*` specs run in a persistent context on a throwaway profile directory (`launchPersistentContext`); the app itself falls back to the 48 MB memory store there. The M00a/M01c `@telemetry` test expects `app.start.store` `opfs` on Chromium and `memory` on `webkit-webgl2`. | AC-5 needs real OPFS on WebKit. A persistent context has it (probed: root ok, `createWritable` present; `createSyncAccessHandle` exists in workers only). The ephemeral result is the case R-PLAT-01 rule 6 describes (no OPFS), so it is also covered. | Give the WebKit project a persistent context in `playwright.config.ts` and drop the per-project expectation. |
| BD-002 | M01e | QA builds read the catalog from the same-origin mirror: pointer `/media-local/asset-catalog.json` (written by `--pointer-out apps/web/media-local`), media base `${origin}/media-local`, and prefer it to `hosts.media` when present. Production builds use `hosts.media` and `/asset-catalog.json`, and are `disabled` while `hosts.media` is empty. The string `/media-local` reaches the client only through `InitParams.localMedia`, set under the compile-time `VITE_DV_QA === '1'` literal, so `verify:dist` can reject it. | `HOST_MEDIA` in `wrangler.jsonc` holds placeholder hosts (`tha-bay-media.workers.dev`), not empty strings as the milestone assumed, so "use `hosts.media` when non-empty" would fetch a host that does not exist. The committed `apps/web/public/asset-catalog.json` is also stale against the M01f lock (its git stamp differs), which the mirror's own pointer avoids. | Delete the `localMedia` branch in `catalog-client.ts` once `media.<domain>` exists (Q-15). |
| BD-003 | M01e | The catalog loads on first use (an `AssetRef` `get`, `has`, `resolve`, `gc`, `downloadAll`, or the bridge's `catalogState()`), not at boot. `catalogState` takes the values `idle`, `loading`, `ready`, `invalid`, `disabled`, `unavailable`. | A production boot would otherwise request the unprovisioned media host every time. `invalid` is kept for a failed pointer or SHA check as specified; `unavailable` is a fetch failure; `disabled` is no media base. | Call `loadCatalog()` from `createPlatform`. |
| BD-004 | M01e | `@dv/shared` gets a subpath export `./assets` (C07 `c07.ts`). The barrel does not export C07. | The engine needs `resolveVariant` and the catalog types. Adding the export to the barrel risks name clashes with other milestones' edits to it. No contract shape changed. | Re-export from the barrel and change the imports. |
| BD-005 | M01e | `pin(hashes)` adds to a per-session pin set and sets the row flag; `open()` clears persisted pin flags; `unpinAll()` is an extra method on the class and the client. | The interface has no `unpin`, and a pin left from an old manifest would block eviction forever. The loader declares the boot set again on every boot. | Persist pins and add `unpin`. |
| BD-006 | M01e | The store's clock is strictly increasing (`max(now, last + 1)`), and LRU order is `lastUsedAt`, then `createdAt`, then hash. A commit failure (quota with nothing left to evict, or an IO error) does not fail `get`: the verified bytes are returned uncached and a `commit-failed` event is raised. | Two packs touched in one millisecond would otherwise tie. A cache that cannot be written is not a failed read. | Throw `PackUnavailable('quota')` from `get`. |
| BD-007 | M01e | Tabs: `hello` with `(startedAt, id)`, an `owner` answer from a writer (or from an older tab that is still probing), a 200 ms probe window. A read-only tab stays read-only until it reloads. A read-only tab still fetches and verifies packs it lacks, and returns them uncached. | A dying writer cannot hand over without a lock service; reload is enough for v1. The notice is non-blocking. Cross-tab handle behaviour stays UNVERIFIED (U-PLT-16). | Add a `bye` message so a read-only tab can retry the lock. |
| BD-008 | M01e | The shared fetch for a hash ignores any one caller's `AbortSignal`: an aborting caller stops waiting (`aborted`) and the request still completes and caches the pack. Joined callers each get their own copy of the bytes. | One caller's abort must not fail the others, and the worker transfers (detaches) what it returns. | Pass the signal of the first caller to the shared fetch (and accept that it fails the joined callers). `FetchRetry` already aborts the network request when no waiter is left. |
| BD-009 | M01e | `window.__dvBridge.assets` is installed without a `Window` type augmentation (a cast in `bridge.ts`). `get` returns `{byteLength, sha256}`, not the bytes. The e2e specs import the `AssetsBridge` type directly. | `Window.__dvBridge` is declared in `platform/probe.ts`; changing that declaration collides with the parallel M00d and M01b2 edits. `evaluate` cannot return an `ArrayBuffer`. | Extend the `Window` declaration in `probe.ts`. |
| BD-010 | M01e | The QA build step is `apps/web/scripts/qa-media.mjs` (run by the root `build` script as `pnpm --filter @dv/web run media:local`); it does nothing unless `VITE_DV_QA=1`. `closeBundle` of the QA-only Vite plugin copies `apps/web/media-local/` to `dist/media-local/`, and `vite dev` serves it through middleware. The service worker precache ignores `media-local/**`. | `assets:publish` needs `--env`; `staging` is used because `dir:` ignores it. | Move the step into the Vite plugin's `buildStart`. |
| BD-011 | M01e | The `app.start` event waits for the asset worker's `open()` with a 5 s cap. On timeout or failure the worker is dropped, `Platform.assets` is null and the event says `store: 'memory'`. | A hung IndexedDB must not stop the game from starting. | Remove the race. |
| BD-012 | M01e | `storage.persist` is requested by `createPlatform` on the first standalone launch (marker `dv-storage-persist` in `localStorage`); `requestPersist('story')` exists for M05a1. | The milestone puts the call in the store layer but the only caller in v1 is the platform boot. | Move the call into `asset.worker`. |
| BD-M01b2-01 | Default world and `?world=` | The page boots the `civic-graybox` scenario (the M01f fixture) unless a QA build passes `?world=<id>` (`walk-drop`, `physics-drop`); `QaFlags.world` and `QaFlags.touch` (`?touch=1`) are new. The title at "/" stays mounted over the live world (translucent, canvas behind it) and Start hides it; `?debug=1` skips the title. The four M01b1/M01a2 e2e specs that need the cube course now pass `world=walk-drop`. | The milestone says the home page opens on the block and the owner wants it visible; the older specs measure the walking course. | Drop the `world` flag and point the specs at the gray-box |
| BD-M01b2-02 | `quantAxis` rounding | Sign-symmetric: `round(abs(v) * 127)` with the sign restored. `Math.round` alone gives -63 and +64 for the half-radius touch stick, and AC-2 asks for 64 either way. Only exact .5 products differ. | AC-2 (29 px of a 58 px radius is 64). | Revert `quantize.ts` |
| BD-M01b2-03 | Touch controls in C03 terms | The stick writes four analog half-axes `touch:btn:moveRight/Left/Down/Up` plus `touch:btn:sprint` (inside the `touch:btn:${string}` member of `ControlId`); the router treats `touch:` axis bindings as analog like `pad:` ones. Look drag goes into `RawInputState.lookDelta` in pixels; `applyLook` reads it through the `touch:dragR` bindings (3.0 x 0.0025 rad per px x `lookSensitivity.touch`) when touch is the last active device, and through the mouse bindings otherwise. No contract change. | C03 has one `touch:stick:L` id and no way to carry two axes. | Move the half-axes to a C03 minor bump |
| BD-M01b2-04 | Touch details left open | A button reads as held for at least 120 ms (the press edge is still latched once); sprint switches on beyond 1.35 x radius and off below 1.25 x (hysteresis); `TouchLayout.zone` is a rectangle in viewport fractions (S10 leaves `Rect` open, note for M04b2); the layout's buttons are Jump, Camera and Pause only. Pointer Events are used; TouchEvents are the fallback and are ignored once a touch-typed pointer event was seen. Playwright WebKit keeps `pointerType` on synthetic events, so the fallback did not run in CI. | C03 rule 10 numbers; Risks. | Edit `touch.ts` and `default-right.json` |
| BD-M01b2-05 | When the layer shows | Only in play, and when the last active device is touch, `(pointer: coarse)` matches or `?touch=1` is set. The binder listens on the layer, not on `window`, so a hybrid laptop does not switch to touch by itself. Keyboard input is ignored until play starts, so Space and Tab keep working on the title. | Title buttons and links must stay usable. | Attach the binder to `window` |
| BD-M01b2-06 | Vault and footfalls | `registerControlSystems` adds a `vault` resource whose hash writes nothing while no vault runs; `walk-drop` opts out so its goldens (`determinism.walk-drop.json`) are unchanged. With a vault store the character does not auto-step in the air, so a 1.0 m jump plus the 0.4 m step cannot clear a 1.4 m box. The footfall cue is `audio.cue` / `foot.step` from `Anim.sinceTick` modulo 30, 18 and 14 ticks (walk, run, sprint): no new state, and events are not hashed. | AC-6 and the golden rule. | Remove the option and regenerate the goldens |
| BD-M01b2-07 | F3 and F4 | F3 is `client.DebugToggle` in `defaults.kbm.json` (on foot and in the `debug` context); F4 is a QA-only key listener, because C03 1.1 has one debug `ClientAction`. On a touch device `?debug=1` shows the panel from the start. | The contract has no second action; no keyboard on a phone. | Add the action and bind F4 |
| BD-M01b2-08 | Pack delivery | `apps/web` imports the two fixture packs with Vite `?url` (hashed; the 736-byte `l0` pack is inlined as a data URL by Vite's size rule), the page fetches them, and the `p0` bytes are cloned into `BootPayload.config.packs` (53 KB, not transferred, because a crash restart sends the payload again). The provenance record of the `p0` pack also lists the built path `assets/p0-64-64-<vite hash>.pack`, which `provenance:check` needs (the name changes with the bytes, as the record does). M01e replaces this with the pack store. | The milestone says "hashed static files". | Point `grayboxBootConfig` at the store |
| BD-M01b2-09 | IWER and three r186 | IWER 2.6.0 returns `null` for `XRWebGLLayer.framebuffer`, and three's WebGL backend uses it as a WeakMap key on every XR frame (TypeError). Not yet run on a real Quest. | AC-9 needs the emulated session to render. | Drop the shim when IWER returns a framebuffer |
