| BD-M01d-01 | Lock `root` field | `root` is the sha256 of the asset's root provenance record (walk `derived_from[0]` to a record with none), the same value as `ProvenanceSummary.root`, taken from the first variant by id. | 05 section 4.3 names the field without defining it. The catalog's commit sha and `createdAt` come from the last commit touching the lock, which differs in a shallow clone, so a recomputed pointer would not be stable. `assets:verify` skips the pointer so the first publish can create it. | Add a recompute check only if CI always fetches full history. |

### M01b1 (2026-10-19, Builder Claude Sonnet 5.5)

| ID | Topic | Choice | Why and how to undo |
|---|---|---|---|
| BD-M01b1-01 | Transform is the feet | A capsule prefab's `Transform` is its feet; the body is created `halfHeight + radius + skinM` (0.91 m) above. The generic kinematic-target loop in `physicsSystems` skips entities with `CharacterBody`; `onFootSystem` sets the target itself. | Anchors (`CameraAnchor` head 1.7, chest 1.35) are heights above the feet, and the renderer draws the mesh from its feet. Undo by moving the offset into `PrefabRegistry.bodyDesc` and the controller. |
| BD-M01b1-02 | Ownership machine encoding | `Control.pending` (u8) packs the phase (bits 0-2) and the requested owner (bits 3-5); a pending teleport target and the camera lock are a hashed resource `control` (registered by `registerControlSystems`, so `physics-drop` hashes are unchanged). `Ready` is the settled phase of the base owner `OnFoot`; every other owner is entered through Waiting and Entering and left through Leaving. A teleport is a transition of the base owner: 700, 701 (up to 300 ticks), `enterSettleTicks` (15), then 100. The ragdoll stub is 300 for 180 ticks, then 301 (the Leaving phase) for 60 ticks, then 100. | The C01 `Control` schema has no room for more fields. The wait counts 300 evaluations, so the failure lands on the 300th tick after the request. Tunables are in `config/physics.json` `character`. |
| BD-M01b1-03 | Hill factor sign | Grade magnitude from the previous tick's KCC `groundNormalY` (`dsqrt(1 - ny^2) / ny`); whether the move is uphill comes from the horizontal part of a 1 m ray cast's normal under the feet (`castRay`, static group), scaled by the cosine between the move and the uphill direction. Downhill is `min(1.25, 1 + |g| x 0.35)` as in the milestone (`01-engine.md` 2.4 prints `1 - slope x 0.35`, which would slow a descent). | `CharMoveResult` only carries `groundNormalY`. A contour walk across a slope is not slowed. |
| BD-M01b1-04 | Jump integration | `dy = (vy - g dt / 2) dt`, then `vy -= g dt`: the exact parabola at tick times, so the apex is 1.000 m (measured 0.99999) at 60 Hz. A move that is rising is never "grounded". Fall and land labels need 3 ticks without ground contact, except after a jump, so a seam in the heightfield or the first tick (before Rapier's first step) does not flash a fall animation. | Plain Euler would be 0.037 m off the 1.00 +/- 0.05 m limit. Set the debounce to 0 in `onfoot.ts` to undo. |
| BD-M01b1-05 | First-step blindness | Rapier's query pipeline learns about new colliders at the next `step`. `walk-drop` setup runs one `backend.step` after adding statics. Restores are fine (the snapshot carries the pipeline; `control.ownership.spec.ts` checks a restore during a teleport wait). | A general fix would need a Rapier call that updates the query pipeline without stepping; 0.21.0 has none (spec/03). |
| BD-M01b1-06 | Course geometry | The 0.35 m and 0.50 m steps are prisms (a 4 m heightfield cell cannot hold them); the 10 % grade and the 50 degree bank are heightfields (`sim/fixtures/walk-course.ts`, exported through `test/fixtures/world-boxes.ts`). The `physics-drop` ground is unchanged, so its golden is unchanged. | The milestone says "in the heightfield" for all four; a prism is the smallest way to get a step. |
| BD-M01b1-07 | Camera shoulder | The sim does not know the shoulder swap (it is a main-thread action). The Publish stage casts both shoulders: `allowedDistance` is the right one (`follow.shoulder` is `right`), and the left result travels in the side block as `allowedDistanceOpposite` (an extra field beside the C04 directive, not a change to it). The rig picks the one for the shoulder it is on. | Avoids a main-to-sim message for a presentation choice. A shoulder setting in C05 (M04a) can move the choice into the sim later. |
| BD-M01b1-08 | Rig details | `toggleFpTp` flips a player preference; a directive with mode `tp` never overrides it, only `cinematic` and `xr` do. Ease-out is a rate set when the target rises (`gap / easeOutSec`), so any gap takes 0.3 s. First person has no lag. Coming back to third person eases the camera out from the head. A target farther than 8 m from the last anchor snaps. The rig drives a structural `CameraLike`, so it runs in Node tests without three. | The milestone fixes the numbers, not these edge cases. |
| BD-M01b1-09 | Router details | Dead zone: an axis below `stickInner` (0.12) reads 0 and anything above passes unscaled (a rescaling dead zone would make AC-3's 0.6 read 70 instead of 76). `client.Pause` bindings are global: the defaults of every device and context plus anything the player adds, so it works in a context that binds nothing. Hold-to-toggle flips on each press edge. Wheel pulses last one poll. Look is applied by `applyLook` (not by `sample`) so the main loop can run it every frame. | R-ENG-04 and C03 rule 9 say Pause keeps its default; the rest is open. |
| BD-M01b1-10 | `walk-drop` | `physics-drop` plus the course plus `player.default` at (-90, 0, -52) facing +X, driven by a seeded out-and-back bot (`walk-drop-bot.ts`, which imports the bot and is therefore only in the QA suite). It is the page's default scenario; `?debug=1` (new QA flag) makes the canvas fill the window so Pointer Lock and the keyboard go to the game. The default scenario of a production build is also `walk-drop`. | The corner-sized canvas has `pointer-events: none`. M04b1 owns the real play surface. |
| BD-M01b1-11 | Events | `services.events` (a bounded `SimEventLog`, local `SimEvent` type until C06 lands in M04a) carries `control.transition` and `control.refused`; the runtime posts them as a new `events` worker message, and `SimHostImpl.simEvents` keeps the last 100. | "Transitions go to the event ring." The `SimEvent` shape is copied from `01-engine-save-modes.md`. |
| BD-M01b1-12 | e2e on a shared machine | `playwright.config.ts` reads `DV_E2E_PORT` (default 8788). With `reuseExistingServer`, two Builders on one machine would test each other's build. The `@fp-tp` spec shrinks the viewport to 480 x 270: the software renderer draws a 1280 x 720 play view at about 6 frames a second and the sim clamps a frame to 0.15 s of ticks, which would stretch 50 m in 12 s past its budget. | Environment, not product. |
| BD-M01b1-13 | Package test scripts | `pnpm --filter @dv/engine test -- <name>` runs the whole engine suite: the script is plain `vitest run`, which ignores the filter after `--`. `CLAUDE.md` names `tsx <rel>/tools/ci/run.ts vitest run --dir packages/<pkg>`, but `--dir` hides the root `include` globs (`packages/*/test/**`), so that form finds no tests. Not changed here. | All acceptance proofs still pass because the whole suite runs. A script that expands the filter to `packages/<pkg>/test/<filter>` would restore selection. |
