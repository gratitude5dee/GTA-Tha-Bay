# M02b1 — streaming-lod

## Goal
After this session the game streams a whole baked city instead of the four-chunk gray-box. A new package `@dv/world` holds the `ChunkStore` (interest, priority, residency, eviction) with the statics feed into physics, and the client half: the `l0` mesher running in `asset.worker`, the `ChunkRenderer` with one static `BundleGroup` of ≤ 6 objects per chunk, the `ChunkUploadGate` (≤ 1 chunk upload per frame), cover masks between levels, L1 and L2 rendering, and the backdrop (DEM ring, massing on desktop tiers, skyline cards), drawn from the S11 packs (`l1`, `l2`, `far-bay-*`) that M02a2 bakes (DL-546). The perf scenarios `walk-civic-center` and `route-ferry-ocean-beach` run in CI on the offline `synth` world from M02a1–M02a2; the real `sf` world is checked on the operator's desktop reference. Telemetry `world.stream` is emitted. Facades are flat-colour and landmarks are absent (M02d1).

## Requirements
- R-MAP-01: the baked city is visible and walkable everywhere inside the `play` box.
- R-MAP-02: the rest of the Bay renders as a low-detail backdrop (DEM ring, massing, cards).
- R-PLAT-03: chunk meshing and pack decoding run in `asset.worker`; rendering stays on the main thread with the WebGL2 fallback path proven.
- R-ENG-02: render objects, triangles, upload cadence and cold download per tier are checked by `check:perf` and e2e.

## Scope in
- **Package `packages/world`** (`@dv/world`): `src/sim/**` under the C02 lint and `tsconfig.sim.json` rules, `src/client/**` may use `three`. Import direction: `@dv/world` imports `@dv/shared` and `@dv/engine` (types and registration hooks); `@dv/engine` never imports `@dv/world`. Worker entries are composed in `apps/web/src/workers/` (engine worker core + world jobs and systems); record this as a Builder decision. **Sim-module hook** (DL-651; the code branch has none: `spawn-worker.ts` hard-codes `../../workers/sim.worker.ts` and that worker builds `SimRuntime` with no way to add systems): `packages/engine/src/sim/runtime.ts` exports `SimModule {id, systems: SystemDef[], resources?, onInit?(ctx)}` and takes `modules?: readonly SimModule[]` on `SimRuntimeEnv`; `SimRuntime.boot` adds each module's resources and systems through `SimCore.addSystem` in array order before the first tick, then calls `onInit`; this is the engine sim-module hook M02c1 and M03c use. The body of M01a2's `packages/engine/src/workers/sim.worker.ts` moves unchanged into `packages/engine/src/workers/sim-worker-core.ts` as `runSimWorker(scope, modules)`; the engine `sim.worker.ts` becomes `runSimWorker(self, [])` (engine tests and the default `spawnSimWorker`), and `apps/web/src/workers/sim.worker.ts` calls `runSimWorker(self, [worldStreamingModule])`. The app passes its composed worker through the existing `bootEngine({spawn})` option (`() => new Worker(new URL('./workers/sim.worker.ts', import.meta.url), {type: 'module'})` in `apps/web/src/main.ts`, the literal form Vite bundles), and `apps/web/src/qa/determinism.ts` spawns the same composed worker, so the QA pages run the systems the game runs. Its `mode: 'determinism'` branch (and M04d's `?run=` branch later) keeps building its own sims through `createPhysicsSim` before and without `SimRuntime`, as on the code branch: `modules` apply only to the `SimRuntime` the game boots, so the composed worker leaves the `physics-drop` and `walk-drop` checkpoints equal to the engine-only goldens in `packages/engine/test/golden/determinism.*.json` on every build, with or without a world (DL-696). `asset-core.ts` follows the same pattern for `asset.worker`.
- **Streaming plan** (`config/world/streaming.json` + schema): the table of `02-world.md` §4 per tier; `r0`, `r2`, physics radius and upload bytes must equal the C13 `WorldLimits` of `config/tier-budgets.json` (unit-checked).
- **`ChunkStore`** (`02-world.md` §3 interface, §5.2): focus = position + velocity × 4 s (headset in XR); wanted set per level by AABB-disc test ordered by `distance × dirWeight` (0.55 ahead, 0.85 side, 1.25 behind) with the focus chunk and its 8 neighbours first; requests `p0` `now`, `l0` `soon`, `l1`/`l2`/`far` `idle`; unload at 1.35 × ring radius, LRU among unpinned; memory pressure `soft` evicts L0 beyond 1.0 × ring first, then lowers density and the radius one step (`11-platform.md` §5.6). Runs in `sim.worker` at `SimStage.Streaming`; statics via `toStaticShapeSet` → `PhysicsBackend.addChunkStatics`, ≤ 1 chunk per tick; floating-origin rebase beyond 1,000 m (M01a2 backend). **Pack path sim↔asset (DL-678):** at boot the main thread creates one `MessageChannel` and transfers one port to `sim.worker` and the other to `asset.worker` (M01e's boot-pack transfer stays for the boot set); `ChunkStore` posts `{seq, ref: PackRef, priority}` requests in request order, `asset.worker` answers through `WorldPackStore` with `{seq, bytes}` (transferred) or `{seq, error: PackUnavailable}`, and `sim.worker` queues replies and applies them only at the start of the next tick's `SimStage.Streaming`, in `seq` order, never mid-tick (a later `seq` waits for an earlier one). `ChunkStore` exposes `preload(keys): Promise<void>` (request, wait for every reply, pin) and `pending(): number` for the world scenarios' residency rule (M03b1).
- **Mesher job** (`asset.worker`): `earcut@3.2.4` [research/repos-world.md §5] for roofs and landuse, walls with the 1.5 m foundation skirt, terrain from every 1st/2nd/4th post (desktop/mobile/mobile-low; vertices lie on the physics surface), roads from `p0` segments, trees as one instanced mesh, baked vertex AO (`aAO`). `config/world/mesher.json` profiles (80 / 60 / 40 / 18 tris per building, skip rules of `02-world-bake.md` §6). Output is transferable buffers per render object.
- **`ChunkRenderer` + `ChunkUploadGate`:** per chunk ≤ 6 objects (`terrain`, `buildings`, `roads`, `vegetation`, `furniture` (empty), `extras` (empty)) in one `BundleGroup` with `static = true`, re-recorded (`needsUpdate = true`) only on a LOD swap; each request increments the chunk's `bundleRerecords` counter, reported by `__dvBridge.world.chunks()`, because a render bundle is actually recorded only on the WebGPU backend [research/stack-rendering-platform.md §1.5] and tests need a backend-agnostic oracle (DL-682); ≤ 1 chunk upload per frame on every tier and ≤ 2 MB per frame on `mobile-low` and `xr-quest`, highest priority first; visibility every 8 frames or on a camera jump > 60 m; behind-camera cull at `dot < −0.35`. TSL materials only (flat district palette colour, night window mask hook for M02b2).
- **LOD ladder** (`02-world.md` §5.3): L1 (`z=7`) and L2 (`z=5`) from MASSING, ROADLINE, LANDUSE and HEIGHT sections; cover-mask uniforms (4 × 4 bits) that discard fragments over resident children; 8 m skirts; dithered fades over 0.5 s on desktop tiers, hard swaps on `mobile-low` and Quest; `lodBias` and `buildingDistanceScale` honoured.
- **Backdrop** (`02-world-maps.md` §4.3; R-MAP-02): ring mesh to 80 km on desktop tiers and cards at 20 km (`xr-visionpro`, `mobile`) or 10 km (`mobile-low`, `xr-quest`); massing desktop only; ≤ 3 render objects; ≤ 1 upload at boot. `__dvBridge.world.backdrop()` reports `{ringKm: number | null, cardsKm: number | null, massing: boolean, renderObjects: number, bootUploads: number}` (AC-14; DL-697).
- **Boot** (`02-world.md` §5.1): when the catalog (in QA builds the `/media-local/asset-catalog.json` pointer, M01e BD-002; M02a1 QA build hook) holds `data/world-index`, the app boots the world (else the M01b2 gray-box path). Precedence in QA builds (DL-668 part 2): an explicit `?world=<id>` (`QaFlags.world`, BD-M01b2-01: `civic-graybox`, `walk-drop`, `physics-drop`) wins over a catalog with `data/world-index` and boots that engine scenario on the M01b2 path, so specs that pass `world=walk-drop` see the same scene on every build; with no `?world=` the baked world boots. `?scenario=` (M01c perf flag) never changes the booted world. Production builds parse no flag. The rule is a pure `bootChoice(world: string | null, hasWorldIndex: boolean)` exported from `packages/world/src/sim/streaming/boot.ts`, called by `apps/web/src/main.ts`, with its four cases in `boot.spec.ts`. World boot: boot set = `p0` inside physics radius + 1 chunk, `l0` inside `min(r0, one tile ring)`, `l1`/`l2` around, `far-bay-*`; a pure `bootSet(index, spawn, tier)` in `packages/world/src/sim/streaming/boot.ts`; the sim waits until spawn statics exist; the render fades in after the first `l0` upload; the boot set is pinned.
- **Failure handling** (`02-world.md` §5.6): `PackUnavailable` → "re-downloading district" overlay, sim waits for `p0`; hash mismatch or decode throw → purge, refetch once, then the tile is `failed` (invisible wall, `err.asset`); offline with `p0` missing at spawn → blocking offline message; GPU loss → rebuild chunk GPU objects from resident meshes without refetch.
- **QA and perf:** `__dvBridge.world.chunks()` (resident keys per level, `bundleRerecords` per chunk, uploads per frame, last upload bytes, failed tiles); perf paths `config/perf/paths/{walk-civic-center,route-ferry-ocean-beach}.json` registered with the M01c scenario runner; telemetry `world.stream` (`residentL0`, `missCount`, `uploadP95Ms`, `bytesMB`, 10 % sample, once a minute) added to `names.schema.json`; switches `world.cards` and `world.massing` read from `config/platform-flags.json` (default `true`, read the way `packages/engine/src/platform/tier-config.ts` reads `webgpu.mobile`), never from `BootConfig.flags`: C12 `FeatureFlag` is a closed union without `world.*` members, so a remote downgrade goes through the governor knobs only (DL-698).

- **Perf reports per scenario:** on the code branch `tools/ci/perf-check.ts` already reads `--scenario` (default `graybox-walk`, not validated) and passes it as `DV_PERF_SCENARIO` to `tests/perf/perf-budget.spec.ts`, which writes `test-results/perf.<project>.<tier>.json` with no scenario in the name, and `checkReports` judges exactly those 2 × 4 files. With several scenarios an unfiltered nightly `check:perf -- --fail` would overwrite the reports and judge only the last scenario. M02b1 therefore keys every report as `test-results/perf.<scenario>.<project>.<tier>.json` (the spec and `reportPath`). `perf-check.ts` exports `PERF_SCENARIOS`, the default selection, read from the committed data file `config/perf/scenarios.json` (a JSON array of scenario ids; here `walk-civic-center` and `route-ferry-ocean-beach`), so registering a scenario is a one-line data edit, not a code change; each later milestone that adds a flat-tier `tests/perf` scenario appends its id there and names that edit in its Deliverables (the "all registered scenarios" of M11a1 AC-7; DL-656 part 4); `graybox-walk` stays selectable by name for a build without `DV_WORLD`. `--scenario <id>` selects one id from `PERF_SCENARIOS` or `graybox-walk`, and an unknown id exits non-zero. Before a run (not with `--skip-run`) `perf-check` deletes the selected scenarios' reports, runs Playwright once per selected scenario, and then expects one report per selected scenario × project × flat tier; a missing report is a miss, a warning without `--fail` and an error with it (as M01c already treats a missing report).
