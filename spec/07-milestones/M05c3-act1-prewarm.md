# M05c3 — act1-prewarm

## Goal
Act 1's cutscene refs are either generated once and cached, or shipped as fallback-only, and neither path can overspend. `pnpm assets:gen prewarm` exists. It reads the release's private `cutscene-requests.json`, walks group G1 (the 9 Act 1 refs, `03-story-cutscenes.md` §D9.1), computes each key's estimate, and stops before the running estimate passes this milestone's line of **$16** (DN-S13-02, DL-209). Without `--live` it prints the dry-run plan. With `--live` it submits only misses through route 28, and only when the registry names a `cleared` provider (ADR-GENAI-01) and every character's sheet crops exist. On Workers Free (DL-OWN-08) the Worker runs only the fal-facing steps and hands the key off; the operator's `prewarm --finish` transcodes with the pinned `cut@1` ladder and `ffmpeg` and re-signs (C2PA) each clip off-edge, and the Worker then re-checks the kill, consent and licence gates and publishes it, manifest last (DL-745, DL-748). C2PA re-signing is switched on for production runs, and the release cutscene index records which Act 1 refs are generated and which stay in-engine. If no provider is cleared, which is the default while Q-30 stands, nothing is spent and Act 1 ships fallback-only, fully playable (R-CUT-03).

## Requirements
- R-CUT-01: Act 1 clips come from a cleared provider through the backend, stored in R2 under the deterministic key, generated at most once per key, and labelled AI-generated; otherwise the fallback chain applies.
- R-ENG-03: every paid call follows a cache check (HEAD, then catalog). The spend is estimated before the run and capped at the M05c3 line inside the USD 100 fal programme (DL-OWN-01).
- R-CUT-03 (support): a ref without a clip keeps its DirectorScript fallback, and the index says so.

## Scope in
- `assets:gen` CLI entry with the `prewarm` subcommand. Every other subcommand (`plan`, `run`, `gate`) prints `pending: lands in M10a1` and exits 0.
- `prewarm --release <tag> [--priority 1] [--cap-micros <n>] [--live] [--env staging|prod] [--report]`, plus test inputs `--requests <file>`, `--registry <file>` and `--offline` (no HEAD; every key counts as a miss; refuses `--live`):
  1. Load `cutscene-requests.json` for the tag (PRIVATE artifact from M05c2) and keep the G1 refs in index order.
  2. **Provider gate:** pick the provider by the C07 registry rule (`05-assets.md` §4.5). If none has `status: cleared`, print `blocked: no cleared provider (ADR-GENAI-01)`, make 0 network calls, and exit 0.
  3. **Sheet gate:** a recipe-K ref whose characters lack approved sheet crops (PRIVATE `sheets/<slug>/` lock entries) is `skip: sheet_missing`, estimate $0.
  4. **Cache check:** HEAD `cutscenes/<key>/manifest.json` on the target media host. A ready key is `skip: ready`. On a miss, a key that route 27 reports `pending` (a job running or handed off, below), or that has a `PRIVATE cutscenes-orig/<key>/handoff.json` (checked when the private-bucket pair below is set), is `skip: pending` at $0. The hand-off is a stored `CutsceneJobDO` state that no watchdog, re-arm or unquarantine clears, so a handed-off key is never paid for twice (R-CUT-01).
  5. **Estimate** per ref, by the §D9.1 formula: shots × seconds × provider $/s × 1.5, plus shots × 1.5 × 39,600 micros for recipe-K keyframes. Accumulate, and stop before the running total would pass `--cap-micros` (default 16,000,000). The rest is `skip: over_line`.
  6. Print the plan table (ref, key prefix, status, estimate, running total) and the headroom left in the programme (`budget_program.cap` − `ledger.sumUsdMicros('fal')`).
  7. With `--live`: `POST /api/v1/admin/cutscenes/prewarm {keys[]}` (`OPS_TOKEN`) for the planned keys only. Poll route 27 until every key is `ready` or `failed`, or has its `handoff.json` (below); without the private-bucket pair, polling stops after 30 minutes and prints the keys still `pending` for `--finish`. `--report` prints the ledger delta for this run from `genai_ledger`.
  8. `--finish`: the off-edge half, below.
- Production pipeline config: `C2PA_RESIGN=1` for `prod` (step `resign`, `05-assets-pipeline.md` §6 step 9). `prewarm --env prod --live` refuses to run when the Worker's `/boot` build has it off.
- After a live run, rebuild the release index with `assets:cutscene-index` (M05b2). Ready keys become entries. Non-ready refs keep their DirectorScript and are listed in `docs/releases/<tag>/cutscenes.md` (generated by `prewarm --report`).
- A mock scenario `prewarm-act1` added to `check:pipeline` (Miniflare + `MockFalPort`): the first run submits the planned keys and the second makes 0 `FalPort` calls.
- **Off-edge finish on Workers Free (DL-745, DL-748; replaces the Transcoder Container of DL-232; Containers need Workers Paid, `spec/03-decisions-and-facts-2.md` §8).** Var `TRANSCODE_MODE` in `services/edge/wrangler.jsonc` follows `FAL_MODE`. It is `offedge` where `FAL_MODE` is `live` (production). It is `mock` where `FAL_MODE` is `mock` (staging, previews, tests): the full in-Worker path with `MockTranscodePort`, as M05b1 runs it today. Its fixture clips are 15–21 KB, so no step hashes more than 64 KiB, and M05b1 AC-13's staging fixture prewarm, M05d's demo and M10b's staging drill still reach `ready`. A job refuses to start when `TRANSCODE_MODE=mock` is paired with `FAL_MODE=live`.
  - **Worker, hand-off phase (`offedge`):** `GenJobWorkflow` runs `05-assets-pipeline.md` §6 steps 1–5 as M05b1 built them, with two changes for the 10 ms step CPU. First, `copy-orig` streams the fal output body into `PRIVATE cutscenes-orig/<key>/orig.mp4` without buffering or hashing it. Second, no Worker step hashes a buffer larger than 65,536 bytes; the keyframe and orig hashes move to `--finish`. A `handoff` step then settles the fal spend in the ledger and writes `PRIVATE cutscenes-orig/<key>/handoff.json` (job key, plan and shot mapping, request id, provider, `characters[]`, licence block, spend). It calls `JobSinkPort.handoff()` and ends the job without a manifest.
  - **Hand-off state (`services/edge/src/cutscenes/CutsceneJobDO.ts`):** `handoff()` stores the state `handed_off` and clears `pendingSince`. Route 27 maps `handed_off` to `pending`, so the C12 `CutsceneStatus` shape does not change. The 2 h pending watchdog, the failed-key re-arm and `unquarantine` leave `handed_off` alone: `quarantine` records `blockedFrom: 'handed_off'`, and `unquarantine` restores `handed_off`, never `absent`. For a `handed_off` key, route 28 starts no fal job. It does nothing until `PRIVATE cutscenes-orig/<key>/finish.json` exists, and then starts the publish phase (below). Only a ready manifest, a kill purge (M10b) or an operator reset through the DO ends the state.
  - **Operator, finish (`prewarm --finish --release <tag> --env staging|prod`):** lists the `handoff.json` objects that have no `finish.json` and no ready manifest. It downloads each `orig.mp4` and runs §6 steps 6 and 8–10 on the workstation through M05b1's ports.
    - `FfmpegTranscodePort` (Node) runs `services/pipeline/transcoder/ladder.sh` (`cut@1`, unchanged) with `ffmpeg` and `ffprobe` as separate processes (DL-629). It refuses unless `ffmpeg -version` reports the version pinned in `spec/03-decisions-and-facts.md` §7 (`6.1.1-3ubuntu5`) and `ffmpeg -hide_banner -encoders` lists `libx264` and `libwebp`, the two encoders `ladder.sh` calls.
    - The pin is the Ubuntu 24.04 archive package `ffmpeg=7:6.1.1-3ubuntu5`. On Ubuntu 24.04 the operator installs it with apt. On any other OS, `--ffmpeg docker` runs `ladder.sh` in a local image built from `services/pipeline/transcoder/Dockerfile.ladder` (`ubuntu:24.04` plus that one package, no server, no Node) with `docker run --rm`, as a separate process that ships nothing of its own (DL-629).
    - `qa-gate` uses `ffprobe` frame counts plus black-frame, freeze and loudness checks.
    - `C2paNodeSignPort` re-signs each rendition with the pinned `@contentauth/c2pa-node` (`spec/03` §7), using `C2PA_CERT_CHAIN_PEM` and `C2PA_KEY_PEM` from the operator's shell. It then reads each signed rendition back with the same package's `Reader.fromAsset`, the call `services/pipeline/fixtures/sign-fixtures.ts` already makes. It refuses unless the active manifest has `orig.mp4` as an ingredient and the only validation code is `signingCredential.untrusted` (expected for a self-made root, `spec/03` §7).
    - `subs` writes the scripted VTT. `--finish` hashes every file and builds the manifest with the same builder the Workflow uses.
    - Upload: the files go to `PRIVATE cutscenes-orig/<key>/out/<runId>/`, and `finish.json` follows as a separate, last upload. `finish.json` holds the run id, every file with its bytes, SHA-256, content type and cache class, and the manifest body. `--finish` then calls route 28 for those keys (`OPS_TOKEN`) and polls route 27 until each is `ready`, or `refused.json` appears (below).
    - Captions are not run off-edge: the manifest carries no `a.m4a` (engine audio, which C09 allows), so no speech-bearing audio is exposed before H7.
    - `--finish --env prod` refuses before any upload when the signing credentials are absent.
    - Test inputs: `--local <orig.mp4> --out <dir>` (no R2, no Worker). It writes `<dir>/<key>/` and a one-entry `<dir>/cutscene-index.json` for `check:c2pa --index`.
  - **Worker, publish phase:** route 28 on a `handed_off` key with `finish.json` starts a `GenJobWorkflow` instance in phase `publish`. This phase makes no `FalPort` call.
    1. It reads `finish.json` (at most 64 KiB, hand validator, DL-694).
    2. It runs `gate('resign')` again: kill state, consent and the registry licence status, the same check that runs before step 15 of `services/pipeline/src/steps/cutscene.ts` today.
    3. It copies each listed file from `out/<runId>/` into `MEDIA cutscenes/<key>/` as a stream, one I/O-only step per file, with the content type and `Cache-Control` taken from `finish.json`.
    4. It writes `manifest.json` last (§6 step 11), runs `record` (step 12) and calls `JobSinkPort.complete`.

    The phase stays under 40 subrequests (Free allows 50 per Workflow instance, `spec/03-decisions-and-facts-2.md` §8). A refused gate writes nothing to MEDIA. It writes `PRIVATE cutscenes-orig/<key>/refused.json` with the gate code. A kill leaves the key `blocked` (route 27 `blocked`); any other refusal leaves it `handed_off`. The CLI deletes nothing in MEDIA.
  - **Credentials for `--finish`:** `R2_PRIVATE_ACCESS_KEY_ID` and `R2_PRIVATE_SECRET_ACCESS_KEY` (the operator-shell pair scoped to `tha-bay-private-{staging,prod}`, DL-287; read and write on PRIVATE). `--finish` passes them to M01d's uploader under the names it reads. It never holds a MEDIA key; the Worker writes MEDIA. It also needs `CLOUDFLARE_ACCOUNT_ID` (the S3 endpoint, `rclonePreflight`) and `OPS_TOKEN`.
  - **Uploader edits:** `tools/assets/src/uploader-rclone.ts` gains three operations on M01d's S3-API rclone remote: `download(remoteKey, localPath)` and `putFile(localPath, remoteKey)` (`rclone copyto`), and `readJson(remoteKey)` (`rclone cat`). `putFile` uploads `finish.json` last. The existing per-class `copy` is unchanged.
  - **Not used on Free:** the Media Transformations fallback of §6. Its URL form needs a zone, and the `media` binding's plan availability is UNVERIFIED. A clip whose ladder fails stays a miss and plays its DirectorScript.
  - **Post-upgrade option (owner gate: upgrade to Workers Paid):** the `TRANSCODER` Container (`TRANSCODE_MODE=container`) built on `claude/build-m05c3`, and its lifecycle release `claude/release-do-lifecycle-3` (DO class `TranscoderContainer`, tag `web-v3`), are **parked, not merged**. A deployed migration tag cannot be rolled back, and a `containers` key fails on Free. The ladder script stays at its path so the Container can reuse it. CI keeps `MockTranscodePort` either way.

## Risks & fallbacks
- **No cleared provider (default, Q-30):** the milestone is complete with a fallback-only Act 1. AC-13 is reported as "Blocked on: ADR-GENAI-01 / Q-30", and `docs/releases/<tag>/cutscenes.md` lists all 9 refs as in-engine.
- **Sheet crops absent (M10a not run yet):** G1 refs are `sheet_missing`. Re-run after M10a2 with the same cap minus what was already spent (`--cap-micros` = 16,000,000 − ledger delta).
- **Billing of refused or errored requests is UNVERIFIED (U-COST-3):** the plan assumes they are billed. The ledger settles from billing events, and any loss comes out of the $2 buffer, never out of M10b's share of the cutscene line (DL-740, DL-741).
- **Workflow step CPU on Free (10 ms, RISK-31):** the Worker steps are I/O-bound by design (AC-9); on the first live run the operator reads the dashboard metric "Exceeded CPU Time Limits" for `tha-bay-web` and records it in the report; a step that exceeds it moves to `--finish`.
- **A handed-off key is never finished** (operator away): it stays `handed_off` (route 27 `pending`) and plays its DirectorScript. No watchdog, re-arm or unquarantine returns it to `absent` (AC-9), and prewarm skips any key with a `handoff.json`. `handoff.json` and `orig.mp4` stay in PRIVATE, and the next `--finish` picks them up. The spend is already settled, so nothing is paid again.
- **A character is killed, or a provider de-cleared, between the hand-off and `--finish`:** the Worker's publish phase re-runs `gate('resign')` before anything reaches MEDIA (AC-14); the CLI never writes MEDIA.
- **Worker copy CPU:** the publish phase only streams R2 to R2; the first live `--finish` reads "Exceeded CPU Time Limits" with the hand-off run (RISK-31).
- **H3-family US licence (U-AST-16) unresolved:** production refuses `pending` providers by registry rule. Previs jobs never feed the release index (CI fails an index that references `previs/`).
