# M00f — third-party-reuse-gates

## Goal
After this session the repository can take vendored third-party files safely. `license:scan` accepts `third_party/` only through the register checks of ADR-REUSE-01 (`docs/legal/third-party-reuse.json`), the build emits `apps/web/dist/third-party-licenses.txt` (and a `THIRD_PARTY_LICENSES.txt` in any distributable package that holds a ported file) and `credits.json` carries every vendored `NOTICE` line, `third_party/**` is neither linted, tested, imported nor bundled outside the bake tools, the operator has a subset-extraction tool for data files, an in-repository clone check fails ported code that lacks its attribution header, a Mapbox scan keeps Mapbox hosts, tokens and sources out of the repository and the build, `license:scan` also refuses GPL-family exceptions and checks the dependency licences of `services/*` and the distributable packages, and the PR template carries the clean-room attestation and a separate vendoring attestation. Every rule is a no-op while `third_party/` does not exist, so the deployed app is unchanged. These checks are the mechanical stop for vendoring: nothing may be vendored before this milestone merges (DL-607).

## Requirements
- R-IP-01: original content only; code or data from another repository enters only as allowlisted, attributed `third_party/` files, and the gates fail anything else (D-31, ADR-REUSE-01).
- R-ENG-01: each gate is a deterministic `pnpm` command with fixture trees and runs in CI.

## Scope in
1. **Licences files.** New `tools/ci/third-party-licenses.ts`, run by root `build` after the Vite build: for every register entry with verdict `REUSE-WITH-ATTRIBUTION` and a `pinnedSha`, it appends to `apps/web/dist/third-party-licenses.txt` a header (the entry's `name`, each item's SPDX id, URL, SHA and each item's full `third_party/NOTICE` line verbatim in the register's `noticeLine` format `<name>/<path> | <spdx> | <creator> | <licence URL> [| modified]`; DL-523, DL-617) followed by every `licenceFiles` file of the entry verbatim (the upstream `LICENSE`, an Apache `NOTICE`, the grant or credit excerpts; DL-630); no vendored entry → no file. Given a package directory, the same tool writes that package's `THIRD_PARTY_LICENSES.txt` for every entry a ported file in it names; `tools/cli`, `packages/mod-sdk` and the kit that `dv init` copies list that file in their `files` (pack) set once they hold a ported file (DL-507).
2. **`license:scan` rules for `third_party/`.** Repository mode reads only `<root>/third_party/` and skips `tools/ci/fixtures/**` in every source scan of items 2, 7 and 8; tests pass a fixture root explicitly (DL-618). Fail when a `third_party/<name>/` directory has no `REUSE-WITH-ATTRIBUTION` entry whose `name` is `<name>`, no `pinnedSha`, no `licenceFiles` item for the upstream `LICENSE`, no `licenceFiles` item whose `spdx` matches each distinct `spdx` of its `allowedPaths` items (a dual-licensed upstream needs the data grant as well as the code `LICENSE`), a `licenceFiles` path that is missing, or a file outside `allowedPaths` and `licenceFiles` (DL-630). Check each `allowedPaths` item, never the entry: `spdx` MIT or Apache-2.0 for `kind: 'code'`, CC-BY-4.0 for `kind: 'data'` (DL-508), and the root `REUSE.toml` annotation for its path carries the same `spdx`. A `*.subset.json` must have `modified: true` and keys exactly equal to its item's `fields` names; `fields` may not name a name, description, tagline, URL, logo, person or coordinate field, nor an address, city, neighbourhood or district, location, OSM id, building id, footprint-link or other geocoded field, and each entry carries its reviewer `note` (DL-523). Mechanically, a `fields` name or `.subset.json` key is excluded when it matches any of the register's `excludedFieldPatterns` (case-insensitive regular expressions, `excludedFieldRule`), and each kept field must be a closed enumeration of at most 32 distinct values in the subset; when `DV_NAMES_REAL_JSON` is set, the NameRegistry real-side matcher runs over every subset value (absent → `SKIP reuse subset values: DV_NAMES_REAL_JSON not set`; DL-648). A `third_party/NOTICE` line that does not parse in the `noticeLine` format fails, and a `kind: 'data'` item whose line lacks the licence URL, or lacks "modified" when `modified: true`, fails. When `apps/web/dist` exists, `apps/web/dist/credits.json` must hold the `NOTICE` line of every vendored item that a "Portions from" header or a C07 provenance record's `derived_from` names. Every source file with a "Portions from `third_party/<name>/<path>`" header must resolve to an entry whose `allowedPaths` holds that path, carry the upstream copyright line verbatim and an `SPDX-License-Identifier` line, and, when `apps/web/dist` exists, that entry's `LICENSE` text must appear in `third-party-licenses.txt`. A package whose `pnpm pack --dry-run` file list holds a "Portions from" file but no `THIRD_PARTY_LICENSES.txt` fails. Two dependency rules are added beside M00b's, which stay as they are (DL-634): any `config/license-allowlist.json` `exceptions` entry whose licence matches `GPL-*`, `AGPL-*` or `LGPL-*` fails whatever ADR id it carries; and the production-dependency licence check of M00b runs for every `services/*` package and every distributable package (`tools/cli`, `packages/mod-sdk`, once each has a `package.json`) as well as `@dv/web`.
3. **Never bundled, never linted as ours.** `third_party/**` joins the ESLint `globalIgnores` and the root `vitest.config.ts` `exclude`. ESLint `no-restricted-imports` (pattern `**/third_party/**`) applies to every importer except `tools/{map,assets,ci,soul}/**` (ported code is copied, never imported; those tools may read vendored data to write derived `content/` files). For `services/edge/src/**`, merge the `**/third_party/**` pattern into M00e's entry for that glob (one `no-restricted-imports` holding both pattern sets), never a second config object for it: in flat config the later matching object replaces the rule's options, which would drop one restriction (DL-649). A small Vite plugin in `apps/web/vite.config.ts`, registered in both `plugins` and `worker.plugins` (Web Worker bundles such as `sim.worker` run only `worker.plugins`), collects every bundled module id (`generateBundle`, each output chunk's `moduleIds`) and merges it into `apps/web/.dv-build/module-ids.json` (cleared at the main build's `buildStart`, never overwritten by a later build; git-ignored, outside `dist/`, so it is never deployed; DL-649), and `check:bundle` (`tools/ci/check-dist.ts` bundle mode, which already runs after `pnpm build` in the `build` job) fails when that file is missing or any id resolves under `third_party/` (DL-618). `names:lint` skips `third_party/` in its source scan and, when `DV_NAMES_REAL_JSON` is set, runs its real-side matchers over `apps/web/dist` as well (absent → `SKIP names real-side dist: DV_NAMES_REAL_JSON not set`).
4. **Subset extraction tool.** New `tools/ci/third-party-subset.ts` and root script **`reuse:subset -- [--root <dir>] <entry> <allowedPath> <upstreamFile>`**, for the operator at vendoring (DL-502 step 3): `--root` resolves the register, `REUSE.toml` and `third_party/` under `<dir>` (default the repository root; tests and the demo pass a temporary tree, so they never write under the repository's `third_party/`; DL-649); reads an upstream JSON or CSV file given by path, keeps only the `fields` names of the named `allowedPaths` item, and writes `third_party/<name>/<path>.subset.json` (canonical JSON, rows in upstream order); it refuses a `fields` list that item 2 would fail, by name pattern or by value rule. It never fetches anything.
5. **PR template.** `.github/pull_request_template.md` carries two mutually exclusive checkboxes (tick exactly one; DL-632). Builder PRs: "No upstream example repository (`research/repos-*.md`) was opened, fetched or searched for this change; no code, data, names, constants or layouts were consulted or copied from any such repository, or copied from any other repository other than declared package dependencies and open-data sources under their own licence rules, except files under `third_party/` listed `REUSE-WITH-ATTRIBUTION` in `docs/legal/third-party-reuse.json`." (DL-508, DL-523, DL-647; it keeps the clean-room attestation of `research/legal-ip-likeness.md` §2.2). Vendoring PRs (operator or Architect only): "Vendoring PR: each upstream was fetched at its `pinnedSha` outside any Builder session, only `allowedPaths` and `licenceFiles` files were copied, every data subset was written by `pnpm reuse:subset`, and `ip:*`, `license:scan`, `names:lint` and `provenance:check` were run." This milestone is the one that edits `.github/` for reuse; the Architect does not (DL-513).
6. **CI placement.** The `ip` job already runs `license:scan` after downloading `web-dist` and after `provenance:check -- --emit-credits`, so the dist rules run in CI: keep it there; no `license:scan` step goes into `static` (DL-618). `static` gains only the `pnpm reuse:clones` step of item 7.
7. **Clone check (DL-616).** New `tools/ci/reuse-clones.ts` and root script **`reuse:clones`**: a token-level clone check (normalised token windows of at least 50 tokens, the threshold of `research/legal-ip-likeness.md` §2.4 `ip:similarity`) between every `kind: 'code'` `allowedPaths` file under `third_party/` and every git-tracked source file outside `third_party/`, `tools/ci/fixtures/**`, `spec/`, `research/`, `prompt-pack/` and `docs/` (at least `apps/`, `packages/`, `services/`, all of `tools/` and `skills/`, so a port into `tools/ci/check-secrets.ts` is covered; DL-648). A match in a file without a "Portions from `third_party/<name>/<path>`" header that resolves under item 2 fails, reporting file and line pairs only. It needs no upstream fetch (`third_party/` is in the repository) and is a no-op without `third_party/`. In-house tokenizer, or a dev dependency at the version pnpm resolves (recorded in `spec/03`). M02c2 and M13a6 Notes cite it.
8. **Mapbox scan (DL-506, DL-616).** `license:scan` fails on `api.mapbox.com`, any `*.tiles.mapbox.com` host, `mapbox://` and the token prefixes `pk.eyJ`, `sk.eyJ` and `tk.eyJ` in `apps/`, `packages/`, `services/`, `tools/`, `content/`, `config/`, `assets/provenance/` and, when it exists, `apps/web/dist`; the rule's own source builds these patterns from fragments, and `tools/ci/fixtures/**` is skipped. `provenance:check` refuses a record whose `source.url` host is `mapbox.com` or one of its subdomains.
9. **Credits lines (DL-631).** `provenance:check --emit-credits` (M00b's writer, extended here) also appends to `apps/web/dist/credits.json`, in its existing entry shape, every vendored item's `third_party/NOTICE` line verbatim and one entry linking `third-party-licenses.txt` (the field mapping is a Builder decision); without `third_party/` it writes exactly what M00b writes. `third-party-licenses.txt` and `THIRD_PARTY_LICENSES.txt` join `NON_SHIP_NAMES` in `provenance-check.ts` (delivery metadata checked by `license:scan`, not by a provenance record; DL-649). Consumer milestones only render these lines.

## Risks & fallbacks
- **M00b's `license:scan` structure resists the per-item rules:** add a separate `scanThirdParty` pass called from `license:scan`, never remove an M00b rule (frozen milestone); log a Builder decision.
- **ESLint flat config cannot express the importer exception cleanly:** two config objects (files `tools/{map,assets,ci,soul}/**` without the rule, everything else with it), and the `services/edge/src/**` entry keeps M00e's patterns beside `**/third_party/**` (item 3); the AC-3 test proves all of them.
- **A `services/*` or distributable dependency on the base fails the widened dependency check:** report it under "Blocked on" and leave it to the Architect; never add an `exceptions` entry for a GPL-family licence.
- **`pnpm pack --dry-run` is slow in CI:** run it only for packages whose tree holds a "Portions from" header (none today).
