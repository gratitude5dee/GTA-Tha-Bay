# M05c4 — offedge-finish

## Goal
A live cutscene job can finish on Workers Free (DL-OWN-08), and `prewarm --live` stops refusing. The Worker runs only the fal-facing steps and hands the key off in a stored `CutsceneJobDO` state that nothing but a publish, a kill purge or an operator reset clears, so no key is paid for twice. The operator's `prewarm --finish` transcodes (`cut@1`, pinned `ffmpeg`) and re-signs (C2PA) off-edge into PRIVATE; the Worker re-runs the kill, consent and licence gate and publishes, manifest last (DL-745, DL-748; split from M05c3 by DL-750). `check:c2pa` verifies the signatures. It must merge before any live prewarm, Act 1 or fighter (M10b). Every AC but the live run (AC-9) runs on Free with no provider or key.

## Requirements
- R-CUT-01: live clips come from a cleared provider through the backend, are stored in R2 under the deterministic key, are generated at most once per key (the hand-off is stored state), are re-signed and are labelled AI-generated.
- R-ENG-03: the hand-off settles the fal spend in the ledger before the job ends. The live Act 1 run stays within the M05c3 line (≤ 16,000,000 micros) inside the USD 100 programme (DL-OWN-01).
- R-CUT-03 (support): a key that is handed off and never finished, or refused at publish, keeps its DirectorScript fallback.

## Scope in
- **`--live` lifted.** M05c3's step 4 refusal is replaced. After the provider gate and the C2PA guard (unchanged, still first), `prewarm --live` sends `POST /api/v1/admin/cutscenes/prewarm {keys[]}` (`OPS_TOKEN`) for the planned keys only. It then polls route 27 until every key is `ready` or `failed`, or has its `handoff.json`. Without the private-bucket pair, polling stops after 30 minutes and prints the keys still `pending` for `--finish`. The cache check also skips, as `skip: pending` at $0, any key with a `PRIVATE cutscenes-orig/<key>/handoff.json` (checked when the private-bucket pair is set). `--report` adds the run's ledger delta from `genai_ledger`.
- **`TRANSCODE_MODE`** (var in `services/edge/wrangler.jsonc`) follows `FAL_MODE`. It is `offedge` where `FAL_MODE` is `live` (production) and `mock` where `FAL_MODE` is `mock` (staging, previews, tests). In `mock` the full in-Worker path with `MockTranscodePort` stays as M05b1 runs it, so M05b1 AC-13's staging fixture prewarm, M05d's demo and M10b's staging drill still reach `ready`. `services/pipeline/src/env.ts` refuses to start a job when `TRANSCODE_MODE=mock` is paired with `FAL_MODE=live`.
- **Worker, hand-off phase (`offedge`):** `GenJobWorkflow` runs `05-assets-pipeline.md` §6 steps 1–5 as M05b1 built them, with two changes for the 10 ms step CPU. First, `copy-orig` streams the fal output body into `PRIVATE cutscenes-orig/<key>/orig.mp4` without buffering or hashing it. Second, no Worker step hashes a buffer larger than 65,536 bytes; the keyframe and orig hashes move to `--finish`. A `handoff` step then settles the spend and writes `handoff.json` beside `orig.mp4`: job key, plan and shot mapping, request id, provider, `characters[]`, licence block and spend. It calls `JobSinkPort.handoff()` and ends the job without a manifest.
- **Hand-off state (`services/edge/src/cutscenes/CutsceneJobDO.ts`):** `handoff()` stores `handed_off` and clears `pendingSince`. Route 27 maps `handed_off` to `pending`, so the C12 shape does not change. The 2 h pending watchdog, the failed-key re-arm and `unquarantine` leave `handed_off` alone: `quarantine` records `blockedFrom: 'handed_off'`, and `unquarantine` restores `handed_off`, never `absent`. For a `handed_off` key, route 28 starts no fal job. It does nothing until `PRIVATE cutscenes-orig/<key>/finish.json` exists, and then starts the publish phase. Only a ready manifest, a kill purge (M10b) or an operator reset through the DO ends the state.
- **Operator, finish (`prewarm --finish --release <tag> --env staging|prod`):** lists the `handoff.json` objects that have no `finish.json` and no ready manifest, downloads each `orig.mp4`, and runs §6 steps 6 and 8–10 on the workstation through M05b1's ports.
  - `FfmpegTranscodePort` (Node) runs `services/pipeline/transcoder/ladder.sh` (`cut@1`, unchanged) with `ffmpeg` and `ffprobe` as separate processes (DL-629). It refuses unless `ffmpeg -version` reports the pin in `spec/03-decisions-and-facts.md` §7 (`6.1.1-3ubuntu5`, Ubuntu 24.04 package `ffmpeg=7:6.1.1-3ubuntu5`) and `ffmpeg -hide_banner -encoders` lists `libx264` and `libwebp`. On Ubuntu 24.04 the operator installs the package with apt. On any other OS, `--ffmpeg docker` runs `ladder.sh` with `docker run --rm` in a local image built from `services/pipeline/transcoder/Dockerfile.ladder` (`ubuntu:24.04` plus that one package; no server, no Node).
  - `qa-gate` uses `ffprobe` frame counts plus black-frame, freeze and loudness checks.
  - `C2paNodeSignPort` re-signs each rendition with the pinned `@contentauth/c2pa-node` (`spec/03` §7), using `C2PA_CERT_CHAIN_PEM` and `C2PA_KEY_PEM` from the operator's shell. It reads each signed rendition back with `Reader.fromAsset`, as `sign-fixtures.ts` does, and refuses unless the active manifest has `orig.mp4` as an ingredient and the only validation code is `signingCredential.untrusted` (expected for a self-made root).
  - `subs` writes the scripted VTT. `--finish` hashes every file and builds the manifest with the Workflow's own builder. Captions are not run off-edge: the manifest carries no `a.m4a` (engine audio, which C09 allows).
  - Upload: the files go to `PRIVATE cutscenes-orig/<key>/out/<runId>/`. `finish.json` follows as a separate, last upload; it holds the run id, every file with its bytes, SHA-256, content type and cache class, and the manifest body. `--finish` then calls route 28 for those keys and polls route 27 until each is `ready`, or `refused.json` appears.
  - `--finish --env prod` refuses before any upload when the signing credentials are absent.
  - Test inputs: `--local <orig.mp4> --out <dir>` (no R2, no Worker) writes `<dir>/<key>/` and a one-entry `<dir>/cutscene-index.json`.
- **Worker, publish phase:** route 28 on a `handed_off` key with `finish.json` starts a `GenJobWorkflow` instance in phase `publish`, which makes no `FalPort` call. It reads `finish.json` (at most 64 KiB, hand validator, DL-694), runs `gate('resign')` again (kill state, consent, registry licence status), copies each listed file from `out/<runId>/` into `MEDIA cutscenes/<key>/` as a stream (one I/O-only step per file, content type and `Cache-Control` from `finish.json`), writes `manifest.json` last (§6 step 11), runs `record` (step 12) and calls `JobSinkPort.complete`. It stays under 40 subrequests (Free allows 50 per instance, `spec/03-decisions-and-facts-2.md` §8). A refused gate writes nothing to MEDIA and writes `PRIVATE cutscenes-orig/<key>/refused.json` with the gate code. A kill leaves the key `blocked`; any other refusal leaves it `handed_off`.
- **`check:c2pa`:** an explicit `--index` that is absent or has no entries fails (only the default index keeps its `0 shipped cutscenes` pass). `--verify-signatures` reads each `.mp4` rendition beside a manifest with the pinned `Reader.fromAsset` and fails on a missing active manifest, a missing `orig.mp4` ingredient, or any validation code other than `signingCredential.untrusted`.
- **Credentials for `--finish`:** `R2_PRIVATE_ACCESS_KEY_ID` and `R2_PRIVATE_SECRET_ACCESS_KEY` (the operator-shell pair scoped to `tha-bay-private-{staging,prod}`, read and write, DL-287), passed to M01d's uploader under the names it reads; `CLOUDFLARE_ACCOUNT_ID` (S3 endpoint, `rclonePreflight`); `OPS_TOKEN`. It never holds a MEDIA key.
- **Uploader edits:** `tools/assets/src/uploader-rclone.ts` gains `download(remoteKey, localPath)` and `putFile(localPath, remoteKey)` (`rclone copyto`) and `readJson(remoteKey)` (`rclone cat`) on M01d's S3-API remote. The existing per-class `copy` is unchanged.
- **Not used on Free:** the Media Transformations fallback of §6 (its URL form needs a zone; the `media` binding's plan availability is UNVERIFIED); a clip whose ladder fails stays a miss and plays its DirectorScript. The `TRANSCODER` Container (`TRANSCODE_MODE=container`, `claude/build-m05c3`) and `claude/release-do-lifecycle-3` (class `TranscoderContainer`, tag `web-v3`) stay parked until the owner upgrades to Workers Paid; `ladder.sh` keeps its path so the Container can reuse it.

## Risks & fallbacks
- **No cleared provider (default, Q-30):** the milestone is complete without AC-9, reported as "Blocked on: ADR-GENAI-01 / Q-30". Act 1 stays fallback-only.
- **Billing of refused or errored requests is UNVERIFIED (U-COST-3):** the plan assumes they are billed. The ledger settles from billing events, and any loss comes out of the $2 buffer, never out of M10b's share of the cutscene line (DL-740, DL-741).
- **Workflow step CPU on Free (10 ms, RISK-31):** the Worker steps are I/O-bound by design (AC-1). On the first live run the operator reads the dashboard metric "Exceeded CPU Time Limits" for `tha-bay-web` and records it in the report; a step that exceeds it moves to `--finish`.
- **A handed-off key is never finished** (operator away): it stays `handed_off` (route 27 `pending`) and plays its DirectorScript. Nothing returns it to `absent` (AC-1), and prewarm skips any key with a `handoff.json`. The next `--finish` picks it up; the spend is already settled.
- **A character is killed, or a provider de-cleared, between the hand-off and `--finish`:** the publish phase re-runs `gate('resign')` before anything reaches MEDIA (AC-6); the CLI never writes MEDIA.
- **Pinned `ffmpeg` unavailable on the workstation:** `--ffmpeg docker` with `Dockerfile.ladder`; the runner refuses any other version (AC-5).
