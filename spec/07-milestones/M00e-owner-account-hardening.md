# M00e — owner-account-hardening

## Goal
After this session the owner's password accounts (owner-merged PR #1, DL-OWN-04, ADR-ACCT-01) conform to the spec. Sign-up (route 58) requires an 18+ attestation and acceptance of the current `TERMS_VERSION`, which this session creates in `config/terms.ts` together with an interim pre-release Terms and Privacy document served by route 66 (`GET /api/v1/legal/:doc`); both are stored server-side as app-level metadata through the Worker's admin path, and sign-in asks again whenever they are missing or stale. Routes 58–61 are rate-limited per net (route 59 also per username), tokens leave `localStorage`, errors map to the C12 envelope, usernames pass the names gate, the account page becomes the non-isolated `/account/` island, and production sign-up sits behind the Worker var `AUTH_PASSWORD_SIGNUP` while sign-in, refresh, logout and `me` keep working. The C12 1.3 additions (`ProviderId` `'password'`, `FeatureFlag` `auth.password`, the DTOs of the account routes; `spec/domains/09-backend-contracts-1.3.md`) land in `@dv/shared`, and a password account can be exported (route 65) and deleted (route 64) through the admin path. No game data is attached to a password account. When the admin path is not recorded (all `ADMIN_PATH` members `false`, the likely case), sign-up answers `feature_disabled`, routes 64 and 65 answer `feature_disabled`, and sign-in keeps working by asking for the attestation at every sign-in without storing it (item 15, DL-643); the PR lists this under "Blocked on: U-ACCT-3, U-ACCT-6".

## Requirements
- R-IP-04: 18+ terms; every sign-up and every stale sign-in carries an `18p` attestation and the current `TERMS_VERSION`, stored only server-side (D-30, DL-602).
- R-AUTH-01: the password credential stays optional and never a phase or tier; single-player needs no sign-in, and `SB` tokens open nothing but routes 61, 62, 64 and 65 (ADR-ACCT-01).
- R-IP-01: usernames pass the reserved list, the display-name distance check and the public denylist before any upstream call.
- R-PLAT-01: `/account/` is the only non-isolated document and loads no game bundle (D-01); every Worker response keeps `withIsolationHeaders`.
- R-ENG-01: every check is a deterministic `pnpm` command over stubbed upstreams; no dashboard step is Builder work.
