# @dv/mode-fighter

The Culture Wars fighter. **M08a1** holds the tools around the pure fight core; **M08a2** is the mode itself: descriptor, sim session, ECS mirror, side camera, gray-box presenter and stage, HUD and screens, Training, the CPU, and the device schemes.

## Where things live

| Path | Holds |
|---|---|
| `packages/shared/src/fight/` | the core (`@dv/shared/fight`): frame-data types, `Int32Array` buffer, input map, parser, states, hits, meters, rounds, projectiles, hash, replay. Sim code under the C02 lint; integers only, no allocation inside `step` |
| `config/fighter.tuning.json` | the FC2 constants table |
| `content/fighter/kits/*.json` | the reference kit `PLAYER_FIGHTER` (FX3, final Showstopper, Shutdown and Taunt) and the eight roster kits (FX2); seven are generated by `scripts/gen-kits.ts` from `scripts/kit-knobs.json` (the balance knobs) |
| `content/fighter/{roster,talk}.json`, `ai/habits.json` | the roster rows (slot, kit, soul, `expectedTier`, gray-box assets, stand-in), the authored trash talk, the twelve named CPU habits |
| `config/fame-domains.json` | fame-domain words, the domain each slot reserves, the stage tags a domain forbids (FX4) |
| `src/lint/` | `fighter:lint` rules (schema, derived advantage, startup, recovery, box bounds, reachable hits, reachable inputs, name collisions, cancel-loop search, FX3 reference) |
| `src/qa/script-driver.ts` | `fighter.script`: the C03 `BotInput` (`device: 'bot'`) from a seeded script |
| `scripts/{lint,replay,make-goldens,balance,gen-kits,gen-souls,gen-graybox}.ts` | the CLIs |
| `golden/vs-00{1,2,3}.dvfight` | the golden replays (every 60-tick checkpoint hash); vs-003 is the shooter against the visionary (drones, sine shots, arcs, armor, a summon) |
| `src/sim/` | the mode (C02 lint): `mode.ts` (session, commands), `match.ts`, `cpu/` (FC10 levels), `training.ts`, `camera.ts`, `mirror.ts` (ECS 1280-1283), `slice.ts`, `module.ts` (`SimModule`) |
| `src/ui/` | the UI half: `presenter.ts` (frame-locked clips on `bay_rig_v1`), `graybox.ts` (fighters and the `powell_turntable` arena), `hud.ts`, `menus.ts`, `training.ts` |
| `src/qa/` | QA only: `bridge.ts` (`__dvBridge.fighter`), `debug.ts` (sim ops), `cpu-driver.ts` (`fighter.cpu`), `headless.ts` (the missions runner's descriptor) |
| `content/fighter/{kits,stages,bouts}` | the nine kits, stage `powell_turntable`, bout `bout.a5` |
| `test/` | lint, replay, driver, cpu, schemes, camera, slice, descriptor, story-bout specs; `fixtures/kits/bad-*.json` fail one lint rule each |

## Commands

```bash
pnpm --filter @dv/mode-fighter fighter:lint                          # tuning + every kit, prints the derived frame-data table
pnpm --filter @dv/mode-fighter fighter:lint -- path/to/kit.json      # one kit
pnpm --filter @dv/mode-fighter fighter:replay -- golden/vs-001.dvfight golden/vs-002.dvfight
pnpm --filter @dv/mode-fighter fighter:replay -- golden/vs-001.dvfight --kit scratch-kit.json --force   # names the first bad checkpoint
pnpm --filter @dv/mode-fighter fighter:balance -- --bouts 100        # CPU vs CPU, every pair of the eight kits, both sides; --bouts 1000 is the M08b1 gate
pnpm check:fighter                                                     # the whole fighter content CI (schemas, lint, roster, gates, goldens, balance smoke)
pnpm --filter @dv/mode-fighter fighter:gen-kits                       # rewrite the generated kits from the tables and scripts/kit-knobs.json
pnpm --filter @dv/mode-fighter test                                   # also part of pnpm check:unit
pnpm check:unit -- packages/shared/test/fight                         # the core: parser, hits, scaling, meters, rounds, hash, no-alloc
```

Regenerate the goldens only after a deliberate data or rules change, with the `golden-update` label:

```bash
DV_UPDATE_GOLDEN=1 pnpm --filter @dv/mode-fighter exec tsx scripts/make-goldens.ts
DV_UPDATE_GOLDEN=1 pnpm check:unit -- packages/shared/test/fight/hash-vectors   # packages/shared/test/golden/fight/hash.v1.json
```

## See it (M08a2)

Build a QA build with the gray-box world and open one of these paths (the QA flags exist only when `VITE_DV_QA=1`):

```bash
DV_WORLD=synth pnpm build   # a QA build with the synthetic city; `pnpm dev` also serves QA builds
# then open, on the dev or preview server:
#   /?fighter=demo       two CPUs (Hard against Hard) on the Powell turntable; each run shows the next pairing of the v1 roster (drones against arcs, sine shots against string cancels, armor against patch, poll against pulse): the default look
#   /?fighter=versus     you (slot 0, keyboard, pad or touch) against the CPU
#   /?fighter=training   Training: frame meter, box overlay, record and playback dummy, reset and refill
#   /?fighter=1          only the bridge, `__dvBridge.fighter` (state, step, replay, cmd) and `__dvBridge.fighterStage`
# add &touch=1 for the touch layout, &world=walk-drop for the gray-box world instead of the city
```

Keyboard (Classic): arrows or WASD to move, jump and crouch; `U I O` light, medium, heavy punch; `J K L` light, medium, heavy kick; `Space` Hype; `Shift` dash; `B` block; `T` taunt; `Esc` or `P` pause. Simple scheme: `J` light, `K` heavy, `L` special (hold forward or down for the other two specials), `;` assist, the same movement, Hype, dash and pause. The pause screen lists the move list for the scheme in use.

```bash
pnpm --filter @dv/mode-fighter fighter:bench     # 3 x 10,000 CPU-vs-CPU steps: step p99 <= 0.10 ms, snapshot + restore <= 0.1 ms
pnpm check:e2e -- --project=chromium-webgl2 --grep @fighter-training
pnpm check:e2e -- --project=webkit-webgl2 --grep "@fighter-hash|@fighter-touch"
pnpm check:perf -- --scenario fight-stage --fail
pnpm check:missions -- --mission m.a1.05           # needs the sf bake (dist/world); the real bout plays under the bot
```

## Rules of the data

`onHit` and `onBlock` are derived, never authored: `advHit = hitstun - (A + R - 1)`, `advBlock = blockstun - (A + R - 1)`. A kit that carries them fails the schema. Startup counts the first active frame. Builder decisions: `spec/11-decision-log-builder.md` rows `BD-M08a1-*`.
