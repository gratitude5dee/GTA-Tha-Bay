# Repo study: GrandV TR (Turkish fork of the SebasKitten/Grand-V launcher)

Analysed 2026-10-18 for Dee-Verse: GTA – Tha Bay. Scope: architecture and logic patterns only. Root: `scratchpad/repos/Grand-V` (paths below are relative to it). File:line refs are to the files as cloned.

## 1. What this repo is

GrandV TR is a fork of the **launcher**, not the engine. The engine (the browser port of GTA V: `game.js`, `loader.js`, workers, `game.wasm`, WGSL shaders, the `data/` RPF tree) lives in an external, user-supplied `GrandV-assets/mirror/playgta5.com/` folder and is never in this repository; the launcher only references it by path and by in-file markers. What the repo does contain is a Rust desktop app (`LauncherApp/rust/`, eframe/egui UI + axum/hyper/tokio server) that: serves that static tree over HTTP or HTTPS (`src/server.rs`), implements the game's save/"userdata", batch-range, and log HTTP APIs (`server.rs`, `src/storage.rs`), hosts a two-player WebSocket relay at `/relay` (`src/relay.rs`), advertises itself over UDP for LAN discovery (`src/discovery.rs`), mints a private LAN CA (`src/tls.rs`), and can wrap itself in a Cloudflare Quick Tunnel (`src/tunnel.rs`). On top of the upstream launcher the Turkish fork adds: a redesigned sidebar UI (`src/ui.rs`), a build-time Rust i18n overlay (`src/i18n/generate.rs`, `tr.rs`, `lang.rs`), a DOM-level web i18n/theme/overlay script (`LauncherApp/web-tr/turkce.js` + `strings.tr.json`, 725 keys), a local "Mod Store" helper that scrapes gta5-mods.com (`src/i18n/magaza.rs`), a transactional "install/remove Turkish" routine with backups (`src/i18n/kurulum.rs`), remembered game folder (`src/i18n/klasor.rs`), and a translated troubleshooting guide (`src/i18n/troubleshooting.tr.json`, mirror of `LauncherApp/troubleshooting.json`).

Relationship to the other repos: upstream Grand-V's launcher is what is forked here (its README is kept verbatim at `LauncherApp/rust/README.md`); `shadany7824/playgta5` is cited as the "reference source archive" of the v1 web port, and the sibling clone confirms the data layout both share (`data-manifest.json` = `{mount:"/game/", version, files:[[path,size,mtime],…]}` with 5,814 entries; `kurulum.rs` rewrites exactly that schema). **IP line:** the launcher/server/relay/store/i18n code is independently written Rust/JS, but upstream Grand-V publishes **no license** (README §License), so even that code is "ask the authors" rather than reusable as-is. Everything that touches Rockstar data is off-limits for us regardless: the RPF7 writer and GXT2 parser in `web-tr/oyun_turkce.py`, the language-slot swap (`x64/data/lang/mexican*.rpf`), the Menyoo runtime hook, the asset torrent magnet in `ui.rs:30-95`, and the Menyoo string table (derived from a GPL-3.0 trainer). We use these only as a checklist of features and as *patterns*.

## 2. Pattern cards

### (a) Hosting modes and how the launcher serves the game page
- **Where:** `src/config.rs:9-100` (Settings), `src/server.rs:252-429` (start), `509-558` (per-request pipeline), `559-930` (routes), `src/tunnel.rs:48-131`, `src/discovery.rs:18-122`, `src/main.rs:48-69` (headless).
- **What it does.** `Settings` (persisted as `launcher-settings.json`, unknown fields preserved via `#[serde(flatten)] extra`) has `mode ∈ {device, lan, external}`, `port`, `max_clients`, `max_connections`, `speed_mib`, `https`, `tls_cert/tls_key`, `public_origin`, `cloudflare_tunnel`, `multiplayer`. `bind_ip()` is loopback for `device` and for `external` without direct HTTPS (reverse-proxy/tunnel case), else `0.0.0.0`. Start order (`server.rs:252-310`): resolve folder (`config.rs:105-123` accepts the folder, `GrandV-assets/`, or `playgta5-offline/` by probing for `mirror/playgta5.com/launcher.html`) → validate the asset package against `grandv-assets.json` (`format:"grandv-assets-v1"`, `[path,size]` list, size-only check, `config.rs:125-162`) → LAN mode auto-generates a private root CA (365 d) + leaf (90 d, SANs = localhost, 127.0.0.1, every IPv4) → **bind the listener before persisting any settings** ("a busy listener leaves the old launcher/settings intact", `server.rs:294`) → save access code → spawn the accept loop. The accept loop (`364-420`) enforces a connection ceiling with `ConnectionSlot` (over-limit sockets get a raw `503 … Retry-After: 1` without spawning a task), keeps a "generation" `CancellationToken` so a live port rebind drains old connections after 2 s, and tracks WebSocket upgrades in a `TaskTracker` so stop waits for relay sessions. Per request (`509-558`): LAN mode rejects non-private peers (403); `Limits::admit` caps distinct source IPs (idle entries expire after 120 s, 503 + `Retry-After: 120`); 30 s route timeout; every response gets `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`, `Cross-Origin-Resource-Policy: same-origin`, `Accept-Ranges: bytes` (`496-505`); if `speed_mib > 0` the body is re-streamed in 16 KiB pieces with a per-IP "scheduled" timestamp (`Limits::reserve`, `118-132`) — bandwidth shaping without buffering files. Routes: `/__lan/certificate.cer` and `/__lan/certificate-info` (`{url, sha256}`), deliberately reachable over plain HTTP for first-time trust bootstrap (the TLS listener peeks the first byte; an ASCII-uppercase byte = HTTP method is served plaintext, `430-466`); any other plaintext request → 302 to `https://<ip>:<port>/launcher.html`; `/relay` WS (origin must equal `scheme://host:port` of an allowed host, or `public_origin`; `Sec-WebSocket-Key` sanity; 2048-byte message/frame caps); `POST /__local/port` (device mode only, loopback only, `Origin` + `X-Launcher-Token` constant-time checked; rebinds the port live and answers with the new URL); `/userdata/*` PUT/DELETE/GET-restore; `POST /log` (append to `server.log`, 4 MiB rotation, 256 KiB body cap); `POST /data/batch?gz=1` (JSON `[[name,start,end],…]`, ≤1000 runs, ≤64 MiB total, reply is the concatenated byte runs with `X-Run-Lengths: n1,n2,…` and optional gzip); static GET/HEAD with single byte ranges (416 + `Content-Range: bytes */size`), `application/wasm` and `text/javascript` MIME forced, directory → `index.html`. URL shapes (`155-216`): device → `http://localhost:PORT/launcher.html#local-launch=<32-byte url-safe token>` (capability lives in the fragment so it never hits logs/Referer); LAN share → first non-loopback IPv4; public → `<public_origin>/launcher.html`. **Tunnel:** spawns `cloudflared tunnel --no-autoupdate --url http://127.0.0.1:PORT` (binary beside the exe or on PATH), reads stderr line by line, accepts only an exact `https://<label>.trycloudflare.com` origin (no port/path/userinfo/subdomain, tests at `tunnel.rs:157-200`), 45 s timeout, `kill_on_drop`; the UI polls `Tunnel::finished()` and stops hosting when cloudflared dies (`ui.rs:398-402`); tunnel mode hard-codes the connection limit to 200 (`config.rs:48-54`). **Discovery:** UDP 8014, request `{marker:"GTA5LAN1", nonce(16–128)}` ≤512 B from a private IP, reply `{marker, nonce, port, https, name, fingerprint}` ≤1024 B, 500 ms per-IP rate limit, 256-entry table; the client broadcasts from every interface, listens 1.5 s, dedups by URL, ≤32 results. Headless `--headless --folder … --port … --no-open` reuses the same settings file.
- **For our game:** keep the three-audience model as "offline PWA / LAN-party host / public cloud"; adopt the COOP/COEP/CORP header set in Cloudflare `_headers` (required for WebGPU + SharedArrayBuffer workers); implement the batch-range endpoint as a Worker over R2 for world-chunk streaming (`X-Run-Lengths` is a neat zero-framing trick); use fragment-carried capability tokens for any privileged local endpoint; "bind before persist" and generation tokens for any live config change; a headless mode for CI.
- **Caveats:** per-IP limits are meaningless behind a proxy/tunnel (they say so); the asset validator is size-only (use hashes); single process, no HTTP/2.

### (b) The multiplayer relay
- **Where:** `src/relay.rs` (whole file), WS gate `src/server.rs:632-691`, tests `tests/compatibility.rs:473-517`.
- **What it relays.** Only player poses. Structures: `Relay { code, rooms: HashMap<String, Room>, slots: Semaphore(64) }`, `Room { build, map, peers: HashMap<id, Peer> }`, `Peer { events: mpsc(32), latest: HashMap<sender_id, pose>, wake: Notify, stop }`. Framing: WebSocket **text JSON**, ≤2048 bytes/frame. Protocol 1 handshake (first message within 5 s): `{type:"check"|"join", protocol:1, key, room, build, map}`. Validation (`131-153`): `key` compared constant-time to the host's access code; `room` ≤32 chars `[A-Za-z0-9_-]`; `build` ≤96 chars (dots allowed); `map ∈ {"gta5","env_test"}`; an existing room must have the same build/map ("Room build/map mismatch"); capacity 2 ("Room full"). `check` answers `{type:"checked", players, capacity:2}` and closes 1000 (a pre-check does not reserve a slot). `join` gets a server-assigned 16-hex id, `{type:"welcome", protocol:1, id, peers:[…], hz:20}`; others receive `{type:"joined", id}`; on disconnect `{type:"left", id}` (via `Drop for Membership`, which also deletes empty rooms). Pose message validated by `snapshot()` (`77-99`): `{type:"pose", seq ≤ 2^31-1, model u32, position:[3 finite, |v|≤20000], rotation:[3, |v|≤360]}`; the server **overwrites `id`** (forged ids are ignored, test at `compatibility.rs:501-503`), drops non-monotonic `seq`, and fans out to every other peer. Flow control: token bucket 30 burst / 25 per s per connection ("Message rate exceeded" 1008); outgoing poses are **coalesced** — only the latest pose per sender is kept, so a slow socket never queues stale poses; the event queue is bounded (32) and overflow closes the peer with 1013 "Receiver too slow"; 2 s send timeout → 1013 "Receiver stalled"; ping every 20 s, missing pong → 1008. 64 concurrent relay sessions per host. No lobby list, no persistence, no server authority, no chat.
- **For our game:** this is exactly the shape of a v1 "see other players" layer and maps 1:1 onto a Cloudflare Durable Object per room (WebSocket hibernation): same vocabulary (`check/join/welcome/joined/pose/left`), server-assigned ids, build/world-version agreement, seq-monotonic + coalesce-latest-per-peer, per-socket token bucket. Widen capacity, add a room directory and district-based interest management, move to binary frames when N > 8.
- **Caveats:** 20 Hz JSON is fine for 2–8 players, not for a city; the only auth is the shared code — we need account-bound tokens; "two players per room" is a product limit, not a protocol one.

### (c) The Mod Store
- **Where:** helper `src/i18n/magaza.rs` (routes `58-65`, guard `83-122`, scraper `179-260`, download `297-365`, registry `369-388`); UI `web-tr/turkce.js:341-896`.
- **Search/category/sort.** `GET http://127.0.0.1:8015/magaza/ara?q&kategori&sira&sayfa` → `{items:[…], sayfa, toplam}`. `kategori ∈ {vehicles, player}` (`SUPPORTED`, line 27), `sira ∈ {most-downloaded, latest, most-liked}` (`SORTS`), `sayfa` clamped 1–500, `q` sanitised to alnum/space/dash, ≤80 chars. With a query it fetches `/search/<q>/<sort>[/<page>]`, otherwise `/<category>/<sort>[/<page>]`. **Scraping, not an API:** `parse_cards` splits the HTML on `<div class="file-list-obj">` and pulls `href`, `title`, `img src`, the `<ul class="categories">` tags, the numbers before `" star rating"`, `" Downloads"`, `" Likes"`, and the author after `class="bottom-by"`; the page count comes from `class="pagination" … data-total`. Item shape (Turkish keys): `{sayfa: "/vehicles/<slug>", ad, gorsel, kategori, etiketler[], yazar, puan, indirme, begeni, destekli}` where `destekli` = category ∈ SUPPORTED. Thumbnails go through `/magaza/gorsel?u=` which only proxies `https://img.gta5-mods.com/`, adds `Cache-Control: public, max-age=86400` and `Cross-Origin-Resource-Policy: cross-origin` (needed because the launcher page is COEP-isolated).
- **Download → install.** `/magaza/indir?sayfa=/vehicles/<slug>`: slug must be `/<category>/<slug>` with safe chars and a supported category; fetch the mod page → find the `btn btn-download` href (must start with the page path and contain `/download/`) → fetch the download page (with Referer) → first `https://files.gta5-mods.com/uploads/…` URL → GET with Referer. File name percent-decoded and sanitised to `[alnum . _ - ( ) space]`; extension must be `.zip/.rar/.7z/.oiv`; ≤128 MiB (checked on `Content-Length` and after download); saved to **`GrandV-mods/<slug>/<file>`** (sibling of `GrandV-assets`); reply `{dosya:"<slug>/<file>", boyut, gunluk:[step log]}`. Politeness: global 1 req/s mutex, custom UA, 120 s timeout, requests only on user action. `/magaza/dosya?ad=<slug>/<file>` serves the bytes back to the page (two path parts, no `..`/`\\`). Then the page (`turkce.js:833-895`) drives **the game's own importer**: builds a `File` → `DataTransfer` → sets `#mod-import.files` → dispatches `change` → waits for `#mod-import-preview` to show or `#mod-result` to say rejected/failed → if `#mod-import-choice` appears (several packages inside) it hands over to the Mods dialog → otherwise polls until `#mod-import-confirm` is enabled and `#mod-result` matches /review/ → clicks confirm (≤5 clicks, ≥3 s apart, 300 s cap) → logs the result ("available on next launch"). A toast with the last three log lines links to the full install log.
- **Installed registry / enable / disable / remove.** `/magaza/yerel` lists `{slug:[files]}`; the page calls the game's `GTAUserMods.list()` (records with `id, packName, sourceArchive.name, sourceCredit, models[]`) and marks a store mod installed when a downloaded file name equals a record's `sourceArchive.name` (`turkce.js:650-664`). Store metadata for thumbnails (`{ad, gorsel, sayfa, yazar}`) is cached in `localStorage["grandv-tr-store-meta"]`; packages without metadata are shown as "Installed outside the store". Enable/Sandbox-traffic/Story-traffic switches simply click the game's own checkboxes `#mod-enable-<id>`, `#mod-sandbox-<id>`, `#mod-story-<id>` (tri-state `aria-checked=mixed` when a slug maps to several records); Remove clicks `#mod-options-<id>` → `#mod-remove` → `#mod-remove-confirm` and waits ≤30 s for the row to disappear; the downloaded archive stays in `GrandV-mods/`.
- **Why only vehicles and characters.** `SUPPORTED = ["vehicles","player"]` because those are the categories the browser port's importer can convert; script mods (.asi/.dll) have no runtime. Upstream's mod system, as visible in `strings.tr.json`: ≤64 packages, 512 MiB combined; package kinds = vehicles (add-on DLC or stock replacement), world props, replacement shaders (hash-matched WGSL packs), textures, handling packs (`handling.meta` field merge), weapons, raw resource containers, LUT colour grading, map folder import, Menyoo XML presets (32 scene entities / 64 presets); traffic injection ≤16 models, ≤3 instances per model; "mod profiles" export the selection + traffic + trainer + save-profile choice; "Mods cannot be combined with multiplayer yet."
- **For our game:** keep the UX (Explore/Installed tabs, category gating with an explicit "unsupported" state, per-step install log + toast, enable/disable without uninstall, "installed outside the store" detection, infinite scroll by sentinel) but replace scraping with a first-party catalogue API (D1 + R2) and replace DOM-driving with a programmatic `mods.import(blob, {source})` promise. **Caveats:** scraping is brittle and ToS-sensitive; the slug→record match by file name is heuristic; everything runs on the host machine, so remote players cannot use the store.

### (d) Save profiles on the main screen
- **Where:** `web-tr/turkce.js:927-980` (picker), `1085-1122` (save status), server side `src/storage.rs`, tests `compatibility.rs:264-350, 663-676`.
- **What it does.** The picker uses the game page's `window.GTASaveProfiles` API: `list() → [{id,name}]`, `selected()`, `select(id)`, `create(name) → {id}`, plus a `gta-save-profile` window event; `"default"` is a pseudo-profile backed by the existing saves. Limits (from strings): names 1–80 chars, unique, ≤64 profiles; each profile has separate Story and Sandbox saves; export/import/"undo import" act on the selected profile. Server-side the browser mirrors saves to disk: `PUT /userdata/<32-hex profile>/<base64url(/userdata/...)>` with `X-Userdata-Mtime` (ms), ≤32 MiB per file, ≤64 MiB per profile; `DELETE` writes a tombstone (`.tombstones.json` = `{relpath: deleted_ms}`, legacy array form accepted); `GET /userdata/<profile>` returns `{files:[{path,data:b64,mtime}], tombstones:[{path,mtime}]}` so a fresh browser can restore without resurrecting deleted files; writes are atomic (temp file + fsync + rename, `storage.rs:22-42`); paths are validated against Windows reserved names and symlink escapes (`43-88`). The overlay also hides the in-game "Save data: …" HUD line and re-surfaces the last status (with timestamp, red if error) on the launcher's main screen via `localStorage["grandv-tr-save-status"]`.
- **For our game:** adopt profile = `{id: 32-hex, name, created}`, per-profile Story/Sandbox namespaces, tombstones with timestamps for cloud sync (KV/D1), mtime round-tripping, and a "last save status" line on the home screen.

### (e) The i18n overlay ("translation applied at build/run time; upstream files stay unchanged")
- **Where:** `LauncherApp/rust/build.rs:7`, `src/i18n/generate.rs`, `src/i18n/tr.rs`, `src/i18n/lang.rs`, `src/i18n/mod.rs`, `src/main.rs:2-3`; web: `web-tr/turkce.js:1163-1232`, `kurulum.rs:84-114`.
- **Rust layer (compile-time source rewriting).** `main.rs` declares `#[path = "i18n/mod.rs"] mod ui;` so `src/ui.rs` is never compiled directly; `mod.rs` does `include!(concat!(env!("OUT_DIR"), "/ui_i18n.rs"))`. `build.rs` calls `generate(tr::UI, tr::KEEP_ENGLISH)`, which reads `src/ui.rs` as text and tokenises it (`generate.rs:41-109`): skips `//` and `/* */` comments, char literals, raw and byte strings; for every ordinary string literal it checks the context (`120-203`): literals that are match patterns (`"x" =>`, `"x" | "y"`) or `const/static` initialisers are left alone; `include_str!/include_bytes!` paths are rewritten to absolute `CARGO_MANIFEST_DIR/src/…` (because the generated file lives in OUT_DIR), and the troubleshooting include is wrapped in `crate::ui::lang::help_json(...)`; a literal that is the first argument of `format!` becomes `tr_format!("en", "tr", …)` (only if the `{placeholder}` sets match, `205-219`); any other literal found in the `tr::UI` table becomes `crate::ui::lang::t("en")`. Untranslated display-like literals (contain letters, a space or capital start, no `://`, not in `KEEP_ENGLISH`) are written to `OUT_DIR/eksik-ceviriler.txt` and reported as a `cargo:warning`. The generator then **injects** code at known anchors (`256-321`): a `language_bar(ctx, Some((&self.folder, &mut self.status)))` call at the top of `fn update`, a generated `__i18n_reload()` that re-parses the help JSON, `klasor::restore/remember` around `app.load()`/`fn load`, and replaces `RichText::new(&self.status)` with `dynamic(...)` which substitutes known backend error substrings (`tr::DYNAMIC`). Runtime (`lang.rs`): an `AtomicBool`, preference in `~/.config/GrandV/language.txt` (`%APPDATA%`/`Library/Application Support` on other OSes), system locale from `LC_ALL/LC_MESSAGES/LANG` or `defaults read -g AppleLanguages`, first-run modal, `help_json()` only uses the Turkish guide if its `updated` date equals the English one.
- **Web layer (DOM mutation).** `turkce.js` is built by substituting `/*__SOZLUK__*/{}` with `strings.tr.json` and `/*__OYUN_YUVASI__*/''` with the game-language slot (`generate.rs:325-341`), installed by inserting `<!-- turkce --><script src="/turkce/turkce.js?v=<sha256[:10]>"></script>` before `</body>` of `launcher.html`, `game.html`, `game.movie.html` (idempotent: an existing marker block is replaced). The language choice lives in `localStorage["grandv-ui-language"]`; the page reloads on change. Translation (`1163-1232`): keys are whitespace-normalised for exact matches; keys ≥8 chars containing whitespace also become ordered longest-first "fragments" so concatenated runtime strings still translate; text nodes, `title/aria-label/placeholder/alt`, and button `value`s are rewritten; `SCRIPT/STYLE/TEXTAREA/CODE/PRE`, contentEditable and anything under `data-tr-skip` are skipped; a `MutationObserver` (childList, characterData, attributes) keeps dynamically rendered UI translated. Menyoo strings are translated at the single choke point where menu text crosses into the engine, via a `globalThis.GrandVMenyooText` byte-map hook (`kurulum.rs:204-229`) — engine-specific, see §5.
- **For our modding/UGC overlay:** this is what third-party UI mods will do to us whether we like it or not, so design for it: stable `data-*` hooks and a `data-ui-skip` attribute; official events (`gta-launcher-settings`, `gta-save-profile`, `ui-appearance-change` are the upstream precedents) and a `BroadcastChannel('game-fps')`-style telemetry channel; a `ui.button({id,label,onClick})` registration API (upstream `GTAGameUI.button`); a string table with ids so translations are data, not DOM surgery; a CI "missing translations" report like `eksik-ceviriler.txt`; date-gated fallback so a stale translation never shadows updated source text.
- **Caveats:** the Rust rewriter is a hand-rolled lexer (no nested raw strings, no `format_args!`), and anchors like `fn update(`/`app.load();` break silently on upstream refactors (they emit warnings, not errors).

### (f) The game-page overlay (collapsible menu, fullscreen, FPS)
- **Where:** `web-tr/turkce.js:1001-1079` (corner buttons), `1125-1162` (FPS), `102-150` (theme), `251-303` (mode cards), `900-923` (Low+ preset).
- **What it does.** On the game page it hides every button in `#game-page-actions` until a fixed-position `⋯` button toggles `.tr-open`; a second button calls `requestFullscreen()` on `documentElement` (webkit fallback) and swaps icon/label on `fullscreenchange`; the corner dims to 35 % opacity in fullscreen and moves down while `#intro-controls` (skip-intro) exists; `pointerdown/mousedown/click` are stopped on the corner so the game never receives them; clicking anywhere else closes the menu. The FPS counter subscribes to `new BroadcastChannel('game-fps')` messages `{fps}` from the engine thread, and its on/off state is a `GTAGameUI.button` entry persisted in `localStorage["grandv-tr-fps"]`. The launcher theme is pure injected CSS using custom properties, `:has()`, `color-mix()` and `prefers-reduced-motion`; accent/tint come from the game's `GTAUIPreferences.load()`; the Play footer becomes `position: sticky`; the Sandbox/Story `<select>` is mirrored by icon cards that dispatch `change` on the original control. "Low+ (tuned)" clicks the game's Low-spec preset then overrides `fxaa=1, anisotropic=4, texturequality=1, lodscale=0.5, drawdistance=500, density=0.5, postfx=1` — a useful view of the settings vocabulary (resolution incl. `native`, fps 24/30/60, low-memory, render scale, geometry stability, shadows).
- **For our game:** ship the collapsible corner menu, fullscreen toggle, and an FPS/telemetry channel natively; expose settings as ids so presets are data.

### (g) Troubleshooting guide structure and the compatibility tests
- **Where:** `LauncherApp/troubleshooting.json`, `src/i18n/troubleshooting.tr.json`, renderer `src/ui.rs:425-486, 880-895`; tests `tests/compatibility.rs`, `tests/asset_package.rs`, `tests/legacy_ca.rs`, unit tests in `server.rs:71-93`, `tunnel.rs`, `magaza.rs`, `kurulum.rs`, `klasor.rs`, `diagnostics.rs`, `ui.rs:1118-1179`.
- **Guide schema:** `{version:1, updated:"YYYY-MM-DD", server:[{title, steps:[…]}], web:[…], sources:[{title, url}]}` — 19 host topics, 16 browser/game topics, 5 external links. Rendered as three tab groups; each topic is a `CollapsingHeader` (first open) with numbered steps; link entries render as hyperlinks; "Guide updated <date>" shown; the Turkish file is embedded with `include_str!` and swapped in only when dates match.
- **Tests worth copying:** a temp fixture folder with `mirror/playgta5.com/launcher.html`, `data/test.bin`, `test.wasm`; `StartOptions { loopback_only: true, advertise: false }` so tests never open LAN ports; tunnel origin swap updates share links and WS origin checks (`94-121`); connection-limit precedence (`124-141`); validation table (access-code trim, reserved Windows names, origin parsing, range parsing incl. suffix/open-ended/multi-range rejection, settings round-trip preserving unknown fields, `163-189`); ranges + batch + gzip + isolation headers + log (`191-262`); save put/restore/delete/tombstone/limits across a restart (`264-350`); capability port change with a deliberately busy port and shutdown proof (`352-435`); bandwidth throttle timing (0.125 MiB/s ⇒ ≥450 ms for 64 KiB) and IP admission via a second loopback address `127.0.0.2` (CI adds `lo0 alias` on macOS, `rust-build.yml:30-32`) (`437-471`); full relay flow incl. wrong key, room full, forged id, out-of-range pose (`473-517`); public-proxy origin rejection (`519-553`); HTTPS/WSS against a generated CA with byte-stable root across regenerations (`555-661`); legacy tombstone list (`663-676`); discovery nonce/cleanup (`678-716`). GUI: headless egui `ctx.run(...)` layout test and a controller test that start/stop/drop release the port.

### (h) Build/release pipeline
- **Where:** `.github/workflows/rust-build.yml`, `build-macos.sh`, `LauncherApp/rust/build.rs`, `packaging/Info.plist`, `packaging/com.grandv.backendlauncher.desktop`, `Cargo.toml`, `.cargo/config.toml`.
- **What it does.** Matrix `windows-latest`, `macos-14` (arm64), `macos-15-intel`, `ubuntu-22.04`; `permissions: contents: read`; path-filtered triggers; `cargo test --locked --all-targets -- --test-threads=1` then `cargo build --locked --release`. Windows: copy to `dist/$GrandV back-end host.exe`, run `--ui-smoke --no-open --ui-screenshot ui-smoke.png` hidden and fail if the screenshot is missing. macOS: assemble `.app` (binary, `Info.plist`, `.icns` generated with `sips`/`iconutil` from the build-script's trimmed icon), `plutil -lint`, ad-hoc `codesign --sign -`, `codesign --verify --deep --strict`, zip with `ditto --sequesterRsrc --keepParent`, then **re-extract the zip, verify again and run the smoke from the extracted app**. Linux: `xvfb-run` smoke, tarball with `.desktop` + PNG. ### (i) "Install Turkish / Remove Turkish" — transactional install with backup and restore
- **Where:** `src/i18n/kurulum.rs:54-75` (idempotent checks), `78-159` (install), `163-200` (uninstall), `204-229` (versioned hook migration), `244-273` (manifest/listing updates), test `279-333`; Python twin `web-tr/oyun_turkce.py:203-258`.
- **What it does.** *Detect:* "installed and current" = page contains `turkce.js?v=<hash>` and the slot file's size equals the embedded payload (and optional video size matches); "removable" = page contains the marker and `turkce-yedek/` exists. *Install:* create `GrandV-assets/turkce-yedek/`; for each page back up the original **once** (only if it lacks the marker and no backup exists), then replace an existing marker block or insert before `</body>` (bail if `</body>` is missing); for the engine hook, undo a previous version's edit from its backup first (migration), back up the runtime, and **skip rather than fail** if the choke-point line is absent; for data files, **refuse** if the file already looks modified (`OPEN` magic at bytes 12..16) but no backup exists, so a corrupted state is never recorded as "original"; write the payload; bump `manifest.json` `version` to `<base>-tr-<sha256(payload)[:8]>` so the game's cache invalidates exactly once, update sizes/mtimes; update `grandv-assets.json` sizes so the launcher's integrity check keeps passing. *Uninstall:* copy every backed-up file back, refresh the listing, delete `turkce/`. The test installs twice (idempotent), snapshots all tracked files before install, and asserts byte-equality after uninstall plus listing sizes == real sizes. Not atomic (no staging + rename), so a crash mid-install leaves a mixed state — but the backups make recovery possible.
- **For our game:** this is a sound minimal design for mod install/uninstall: back-up-once keyed by path, marker-based idempotent patching, cache-busting version bump, integrity listing kept in sync, refuse-to-backup-modified-files, and a byte-equality uninstall test. Add a journal/receipt and staging+rename for atomicity.

## 6. Recommendations for our spec

1. Serve every game response with COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, `Accept-Ranges: bytes` — put them in Cloudflare `_headers`, and give the asset validator hashes, not sizes.
2. Implement a `/data/batch` style multi-range endpoint (JSON runs, `X-Run-Lengths`, optional gzip, ≤64 MiB) as a Worker in front of R2 for world-chunk streaming.
3. Model hosting audiences as `offline-pwa | lan-host | public`; keep the LAN-host path (private CA bootstrap over plain HTTP at `/__lan/certificate.cer`, UDP discovery with nonce) as an optional desktop shell, not core.
4. Start multiplayer as a pose relay in a Durable Object per room with the `check/join/welcome/joined/pose/left` vocabulary, server-assigned ids, world-version agreement, monotonic `seq`, coalesce-latest-per-peer, per-socket token bucket, bounded queues with "receiver too slow" closes.
5. Plan the authoritative server (vehicles, traffic, missions) as a separate phase; the relay's "pre-check does not reserve a slot" rule and room capacity should survive into it.
6. Mod manifest fields to adopt: `id/slug`, `name`, `author`, `category` (with an explicit installable set and an "unsupported" state), `thumbnail`, `sourceArchive {name, sha256, size}`, `models[]`, `enabled`, `sandboxTraffic`, `storyTraffic`, `installedFrom (store|local)`, `installedAt`, plus store-side `downloads/likes/rating`.
7. Design the install transaction as a receipt/journal: back up originals once keyed by path, stage into a temp dir then rename, marker-based idempotent patching, bump a manifest version for cache busting, keep the integrity listing in sync, refuse to "back up" already-modified files, and test uninstall by byte-equality.
8. Expose a programmatic importer (`mods.import(blob, {source}) → Promise<Report>` with preview/multi-package-choice/confirm states) so the store never has to click DOM buttons.
9. Store UX: Explore (search, category, sort = most downloaded/latest/most liked, infinite scroll) and Installed (enable/disable/traffic switches, remove, "installed outside the store"); per-step install log + three-line toast; thumbnails via a CORP-cross-origin image proxy.
10. Never scrape third-party sites; our catalogue is first-party (D1 metadata, R2 archives, size cap 128 MiB, allowed extensions whitelist, sanitised file names).
11. Save profiles: 32-hex ids, named, ≤64, "default" pseudo-profile, separate Story/Sandbox namespaces, export/import/undo per profile, tombstones with ms timestamps for sync, mtime preserved; show "last save status" on the home screen.
12. Put every UI string in an id-keyed string table; ship a CI "missing translations" report; gate overlay translations on a source `updated` stamp so stale translations fall back.
13. Treat the DOM-mutation overlay as the de-facto UI-mod API: provide `data-ui-skip`, stable element ids, official window events, a `ui.button()` registration API and a `BroadcastChannel` telemetry feed (`fps`, load step) so overlays don't scrape.
14. Ship natively: collapsible corner menu, fullscreen toggle that swallows pointer events, FPS counter, reduced-motion-aware theme using CSS custom properties.
15. Expose graphics settings as ids (`resolution`, `fps`, `lowMemory`, `renderScale`, `shadows`, `lodscale`, `drawdistance`, `density`, `postfx`, `fxaa`, `anisotropic`, `texturequality`) so presets like "Low+" are data.
16. Build the sandbox feature backlog from §3: player toggles, vehicle spawner by class, mod shop with slot ranges, weapons, bodyguards/companions, teleports (real SF landmarks), weather/clouds/wind presets, time of day/pause/sync, world speed/blackout/population/gravity, object spooner with scene limits, XML/JSON presets with operation caps.
17. Copy the troubleshooting schema (`{version, updated, groups:[{title, steps[]}], sources:[{title,url}]}`) and the first-open collapsible rendering; keep "Guide updated <date>".
18. Copy the test strategy: loopback-only fixtures, a second loopback address for per-IP tests, byte-stable CA regeneration, forged-id and out-of-range relay tests, settings round-trips that preserve unknown fields.
19. If we ship a desktop/LAN shell: Rust matrix CI with a screenshot smoke gate, ad-hoc signing + zip round-trip verification, headless mode, bounded in-app console log (1500 lines / 512 KiB, UTC) that never logs tokens or codes.
20. Keep the IP wall explicit in the spec: no Rockstar formats (RPF/GXT2/OIV), no trainer-derived strings, no references to asset mirrors or torrents.
