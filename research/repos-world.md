## 0. Executive summary

- **None of the three repos uses Google Photorealistic 3D Tiles, Mapbox tiles, or takram's 3D-Tiles integration.** `San-Francisco` (package name `sf-3d`) is a 100 % open-data, zero-API-key, offline-baked city: DataSF lidar building footprints (PDDL), OpenStreetMap via Overpass (ODbL), AWS/Mapzen Terrarium DEM tiles (USGS 3DEP, public domain) and USGS National Map orthoimagery (public domain). The `@takram/three-geospatial` packages are used only for the physically-based sky, aerial perspective and volumetric clouds, not for tiles. This is the right licensing posture for a game and should be the Dee-Verse baseline.
- **The Atlas repo is the cleanest reference for a regional (SF→San Jose→Berkeley) OSM pipeline**: Overpass extracts → coastline ring assembly → way merging → Douglas-Peucker → compact Int16-delta binary → 1 km spatial cells. It is Canvas 2D, not Three.js, but the data pipeline (`build/build_scene.js`, `build/geo.js`) is directly reusable for a region-scale "far world" and for the in-game 2D map.
- **gta-sa-earth is the mission-system reference.** It embeds a real SCM (GTA script) interpreter that *simulates the whole mission once at load* (fixed-step world, 20 k instructions/thread/tick, snapshot every 33 ms of game time), records a typed event timeline (27 event types) plus per-entity tracks, then a player scrubs that timeline with binary search. The auto-director (`Ah` class) picks from a shot vocabulary (chase / flyby / side / front / heli / rearlow / enemy / shoulder / wide), validates shots with BVH raycasts (`segmentHit`), damps with `1-exp(-dt*g)`, and cuts when the subject is occluded for >0.8 s. Its weather/day-night is GTA's `timecyc` table: per-weather × per-hour keyframes interpolated into ~12 uniforms. All of it is engine-agnostic and should be re-implemented (not copied — it is bound to Rockstar file formats, which the brief forbids).
- **Licensing (verified 2026-10-18)**: OSM = ODbL 1.0 (attribution + share-alike on derived *databases*; a rendered game is a produced work). DataSF Building Footprints = PDDL (public domain), rows updated 2026-10-17. Overture buildings/transportation/base/divisions = ODbL; places = CDLA-Permissive-2.0 / Apache-2.0 / CC0 per source. Google Photorealistic 3D Tiles: visualization-only, no pre-fetch/cache beyond HTTP cache headers, no offline, no extraction/tracing/machine interpretation, Google logo + data-provider attribution mandatory, 1,000 free requests/month then $6.00 per 1,000 billable events (Enterprise SKU), 10,000 root-tileset queries/day cap. Mapbox Product Terms (2025-10-01): no tracing/deriving/extracting, on-device cache ≤30 days only via Mapping APIs, mandatory Mapbox + OSM attribution. Google's Gaming Services (Maps SDK for Unity) were deprecated 2021 and are decommissioned.
- **Library status (npm, 2026-10-18)**: `three@0.186.1` (r186 released 2026-09-24), `@takram/three-geospatial@0.9.1`, `@takram/three-atmosphere@0.19.1`, `@takram/three-clouds@0.7.6`, `@takram/three-geospatial-effects@0.6.4` (all 2026-05-06, no release since), `3d-tiles-renderer@0.5.3` (2026-09-18, Apache-2.0), `postprocessing@6.39.5`, `n8ao@2.0.1`, `earcut@3.2.4`. takram's WebGPU/TSL entry point exists (`@takram/three-atmosphere/webgpu`, needs three ≥0.182) but is labelled "Work-in-progress"; the GLSL/WebGL path is the documented one and is slated to be archived once all packages support WebGPU. Safari 26 ships WebGPU on iOS/iPadOS/macOS/visionOS (WebKit blog, 2025-06-09).

## 1. San-Francisco (`sf-3d`) — open-data SF in Three.js

Repo root: `.../repos/San-Francisco`. Single commit (`30d6ce1`). `package.json`: `three ^0.173.0`, `@takram/three-atmosphere ^0.19.1`, `@takram/three-clouds ^0.7.6`, `@takram/three-geospatial ^0.9.1`, `@takram/three-geospatial-effects ^0.6.4`, `postprocessing ^6.39.5`, `n8ao ^2.0.1`, `earcut ^3.0.1`, `lil-gui`, Vite 6, TypeScript 5.7, `tsx` for bake scripts. 11,356 lines of TS under `src/`, ~1,900 under `tools/`. Code comments state the rendering core was ported from `jeantimex/tokyo` (UNVERIFIED on the web; treat as provenance note only).

### 1.1 Coordinate frame (`src/world/coords.ts`)
- Local ENU, origin = SF City Hall `37.7793 N, -122.4193 W`, `+X` east, `+Y` up, `-Z` north. Flat-earth metres: `METERS_PER_DEG_LAT = 110992.06`, `METERS_PER_DEG_LON = 88083.39` (WGS84 radii at 37.78°).
- `WORLD_BOUNDS`: 20 km × 20 km (X −10,500..+9,500; Z −11,000..+9,000) = Ocean Beach → Treasure Island, Daly City → Sausalito/Tiburon. `FAR_BOUNDS`: 80 km × 80 km.
- Slippy-tile helpers (`lonToTileX`, `latToTileY`) are shared by the bake tools; `round1()` quantizes baked geometry to 0.1 m.
- **Why it matters**: a single flat ENU frame keeps every subsystem (physics, roads, buildings, camera, labels) in one metre-space, avoids ECEF/float32 precision issues, and is good enough for a 20–80 km playfield (curvature error is negligible for gameplay; takram's sky still needs an ECEF matrix, which `atmosphere.ts` builds once from the origin).

**Binary cell format (`tools/buildings.ts` L354–391)**: `uint32 count`, then per building an 8-byte header `int16 baseY*10 | uint16 height*10 | u8 r,g,b | u8 nVerts`, then `nVerts × (int16 dx, int16 dz)` at `COORD_QUANT_SCALE = 0.08` m relative to the cell centre. 8 cm precision, ~50 bytes/building. This is a good template for Dee-Verse's world chunks (add a `uint16 kind/style` field for parody-stylization).

**Terrain sampler reuse**: `BakedTerrainSampler` (`tools/terrain.ts` L189) reads the *same* `core_dem.bin` the browser renders so buildings, roads, trees and landmarks are anchored on the exact heightfield mesh. Keep this invariant — physics and visuals must share one heightfield.

### 1.3 Runtime bootstrap (`src/main.ts`)
- `THREE.WebGLRenderer({ antialias:false, powerPreference:'high-performance', stencil:false })`; SMAA handles AA in post. `shadowMap.type = PCFSoftShadowMap`. `renderer.info.autoReset=false`.
- **Pixel budget** (`getOptimalPixelRatio`): `dpr = clamp(sqrt(2,560,000 × qualityScale / cssPixels), 1.0, min(rawDpr, 1.5 × qualityScale))` — caps physical framebuffer at ~2.56 M px.
- **Adaptive quality** (`updateAdaptiveQuality`): EMA of frame ms (α 0.06); if `> 23 ms` sustained for 2 s → `balanced`: clouds `resolutionScale 0.45`, building `maxDrawDistance 8200→6800`, `shadowDistance 1650→1350`, DPR × 0.8. One-way downgrade only.
- **Depth precision** (`updateCameraDepthPlanes`): `camera.near = clamp(clearanceAboveGround × 0.14, 2, 22)`, `far = 65,000` — scales near with altitude so a 24-bit depth buffer survives 20+ km views.
- Startup order: await atmosphere LUT `readyPromise` → terrain/water → landmarks → roads (progressive) → 4 nearest building cells → `renderer.compile()` + one `stepFrame(0.016)` warm-up → dismiss overlay; remaining 32 cells stream in the background.
- `index.html` installs a `requestIdleCallback` polyfill with `timeout: 50` because takram's LUT generator chains idle callbacks and a busy render loop starves it ("leaves the sky black").

### 1.4 Sky, atmosphere, clouds, post (`src/world/atmosphere.ts`, `src/sky/AtmosphereSky.ts`, `src/world/environment.ts`, `src/world/fog.ts`)
- ECEF basis: `Geodetic(lon,lat,0).toECEF()` + `Ellipsoid.WGS84.getEastNorthUpVectors` → `worldToECEF = makeBasis(east, up, -north).setPosition(p)`. Passed to `AerialPerspectiveEffect`, `CloudsEffect`, `SkyMaterial`, `SunDirectionalLight`, `SkyLightProbe`.
- LUTs: `PrecomputedTexturesGenerator(renderer).update()` on the GPU at startup, or `?bakedLUT` → `PrecomputedTexturesLoader({format:'binary'})` from `public/assets/takram/` (used by the headless recorder because the precompute burst can trip Windows GPU timeouts). Cloud assets: `local_weather.png`, `turbulence.png`, `shape.bin`, `shape_detail.bin` (3D textures), `stbn.bin`.
- Clouds: 2 layers (heights 620/750 m, base altitude 450–1,700 m by preset), `shadow.cascadeCount 2`, `mapSize 512`, `temporalUpscale=false` (4×4 checkerboard left a visible grid), `resolutionScale 0.6` (0.45 on software GL), `qualityPreset 'medium'`. The clouds and shadow fragment shaders are **string-patched** to multiply `localWeather` by a city-rect mask (`cityRect`/`cityFade`), and to add a `cloudAmbient` term — fragile across takram upgrades.
- Composer (`postprocessing`, `HalfFloatType`, `multisampling 0`): `RenderPass → WindowReflections → N8AOPostPass (aoRadius 7, intensity 2.2, halfRes) → FogEffect → Scale(0.1) → [Clouds + Aerial] → [plain sky] → Scale(10) → LensFlare → [Balance, Bloom(0.5, thr 0.9, mipmapBlur), ToneMapping NEUTRAL, Grade, Picture, Dithering] → SMAA(HIGH)`. The `Scale(UNITS=0.1)` pair converts scene radiance into takram's units and back.
- `environment.ts`: `SunDirectionalLight({distance:2000})` 2048² shadow, `SkyLightProbe` (SH irradiance), two hemisphere lights, PMREM env map re-baked only when the sun moves `> 0.006 rad` or darkness changes `> 0.04` and at most every 200 ms. Auto-exposure: `toneMappingExposure = clamp(2.25 / luminance, 0.6, 1.7)`. Shadow frustum extent quantized to `180 × 1.3^n` and the target snapped to shadow-texel size to kill shimmer (`follow()`).
- Time of day: `AtmosphereSky.getSFDate(hour)` = June 21 2025 PDT; presets `day 16.2h`, `golden 19.65h`, `fog 16.2h (cloud base 250 m = "Karl the Fog")`, `night 22h`. `night/dark/daylight/warmth` scalars derived from sun elevation via `smoothstep` bands (`night = 1-step(deg,0,9)`, `dark = 1-step(deg,-13,5)`, …) and pushed to shared uniforms so building windows, lamps and traffic lights react.
- `fog.ts`: 20-line analytic exponential height fog in a `postprocessing` `Effect` using depth → `through = density × exp(-eye) × dist × (1-exp(-k))/k`. Cheap and mobile-safe.

### 1.5 Buildings streaming (`src/world/BuildingsLayer.ts`, `src/buildings/BuildingMesher.ts`, `buildingWorker.ts`)
- Worker pool `min(2, hardwareConcurrency>>1)` running `meshBuildingCellBuffer()` (earcut + procedural walls/roofs/parapets/balconies/rooftop equipment; attributes `position, normal, color, aFacade(4), aBldg(4)`), transferring ArrayBuffers zero-copy.
- Priority = distance × direction weight (`0.55` ahead, `0.85` side, `1.25` behind; anything `<1,800 m` always first). `maxConcurrent 2` fetches; **≤1 cell GPU upload per frame**.
- Culling every 8 frames or on a >60 m camera jump: `maxDrawDistance 8,200 m + altitudeBoost (≤2,800)`, always-visible radius 2,800 m, behind-camera cull `dot < -0.35`, shadows only within `1,650 m`. Result: 3.14 M triangles across 36 cells, 60 fps target on integrated GPUs (per `GATES.md` G4).

### 1.6 Roads, traffic, cable cars, trees (`src/world/RoadsAndLanduseLayer.ts`)
- Progressive load: classes `[0,1,2,7]` (freeways, arterials, collectors, cable cars) + piers first, then `[3]` residential, then `[4,5,6,8]` across idle frames (`nextFrame()` = rAF or 24 ms).
- `buildRibbonGeo()` extrudes each draped polyline into casing/fill/centre-line ribbons (`maxSubdivLen 16 m`), skipping segments over water (`sampleGround < 0.45`) and inside hero-bridge corridors.
- **Traffic** (`buildMovingCityTraffic`): candidate routes = ways with `cls ≤ 3`, trimmed at water/bridges, min length 75/110/160 m by class; keep the 320 longest; `laneOffset = clamp(width×0.23, 1.5, 4.8)`; `speedBase 24/15.5/12.5/10 m/s`; up to 540 agents (1–4 per route, alternating direction, 1-in-14 bus/truck scale); four `InstancedMesh`es (body, cabin, headlight, taillight) = 4 draw calls; distance-throttled update. This is *presence* traffic (no intersections, no collision), fine for ambience but not for police chases.
- Cable cars: ping-pong along the 3 canonical routes with `lerpVectors` + `lookAt`.
- Trees: 47,896 instances in 5 `InstancedMesh`es, hidden above 2,800 m altitude; lamps hidden above 880 m; lane markings above 1,750 m.

### 1.7 Camera system (`src/camera/CameraSystem.ts`)
- Pose model `{x,y,z,headingDeg,pitchDeg}` with a `targetPose` and damped follow; URL hash serialization (`parseHash/serializeHash`) for deep links.
- **Walk mode** (first person): eye height 1.7 m, speed 7 m/s (16 with boost), slope factor uphill `max(0.35, 1-slope×1.7)`, downhill `min(1.25, 1-slope×0.35)`, ground from `max(terrain, bridgeDeck)` — reuse for on-foot locomotion feel on SF hills.
- **Cinematic tour**: 12 shots × 7.5 s, each `{startPos,endPos,lookAtStart,lookAtEnd}` in lat/lon/alt via `latLonToENU`, smoothstep ease, ground clamp `+5 m`. **Fly-to**: cubic ease-out + arc boost `sin(πt)·min(550, dist×0.16)`.

### 1.8 Deployment / verification
- `.github/workflows/deploy.yml`: Node 24, `npm run build`, GitHub Pages. `vite.config.ts`: `base:'./'`, `target es2022`, `assetsInlineLimit 0`.
- `scripts/verify-visual-screenshots.mjs`: decodes PNG screenshots and asserts average sky luminance / city luminance variance per view — a cheap "did the sky go black" regression gate worth copying for the Dee-Verse CI (run Playwright headless with `?bakedLUT`).

## 2. SF-Bay-Area-AI-Atlas — regional OSM pipeline and Canvas renderer

Repo root: `.../repos/SF-Bay-Area-AI-Atlas`. MIT code; map geometry ODbL; dataset CC BY 4.0. No map library, no WebGL; one 3 MB HTML. Relevant to us for the **data pipeline** and the **2D in-game map**, not for the renderer.

### 2.1 Projection and extent (`build/geo.js`)
- Local metres, origin mid-Bay `LAT0 37.66, LON0 -122.22`, `MPD_LAT 110574`, `MPD_LON 111320·cos(LAT0)`.
- Scene rect `SW(37.19,-122.56) → NE(37.99,-121.83)`: Marin Headlands to south of San Jose, Pacific shore to Berkeley/Oakland hills (~64 km × 89 km).

### 2.2 Extracts and processing (`build/build_scene.js`)
- Inputs are raw Overpass JSON files in `OSM_DIR`: `coastline`, `water`, `parks`, `motorway`, `primary`, `secondary`, `streets_sf`, `streets_cores`, `rail`, `places`, and 14 `bldg_*` city extracts (`bldg_sf_ne`, `bldg_sf_bay`, `bldg_oak`, `bldg_berk`, `bldg_sj`, `bldg_pa`, `bldg_mv`, `bldg_ssf`, `bldg_sm`, `bldg_rwc`, `bldg_svl`, `bldg_sc`, `bldg_emy`, `bldg_fc`). The Overpass queries themselves are not in the repo (README: "`build_scene.js` expects raw Overpass extracts in an `osm/` directory").
- **Coastline → land polygons** (`assembleLand`): OSM `natural=coastline` ways are directed *land on the left*; `chainWays` joins them by endpoint key (0.1 m), `clipChain` clips to the rect (Liang–Barsky), open chains are closed by walking the rectangle perimeter CCW to the next chain entry (`perim`, `cornersBetween`). Keep rings `> 0.25 km²`; Douglas-Peucker 30 m (>100 km²) else 16 m.
- **Roads**: per-class tolerance (motorway 26 m, primary 24, secondary 30, streets 14); flags `|8 bridge |16 tunnel |32 link`; `mergeWays()` joins fragments sharing an endpoint and class (113 k fragments → ~24 k strokes); `carPaths` = merged ways with class ≤3, ≥4 points, not tunnel, length >1,200 m, top 1,400 by length.
- **Bridges**: deck polylines from OSM motorway ways named `Golden Gate Bridge` (deck 67 m) / `Bay Bridge` (58 m), keep the longest merged carriageway; tower positions hand-listed from OSM `bridge:support` (GGB towers 225 m at `37.81402,-122.47788` and `37.82551,-122.47921`; Bay Bridge 160 m ×4 + centre anchorage 78 m + SAS tower 160 m).
- **Buildings**: dedupe by OSM id; min area 210–420 m² per city file; DP 3 m then 6 m, cap 10 vertices; force CCW; height = `height` tag → `building:levels×3.3+1.2` → `roof:height` → type heuristic (house 6.5, apartments 11/17, commercial 12/22, industrial 10, else 6.5/9/13 by area), clamp 3..340 m, `est` flag; stored as Int32 centroid + Int16 0.25 m local deltas, Uint16 height×4; **sorted into 1 km cells** so the renderer culls whole cells.
- **Packing** (`Packer`): Int32 anchor + Int16 deltas (split when |Δ|>32,000) + Uint16 counts + Uint8 meta, base64 into `data/scene.js` (`window.SCENE = …`).
- **Places**: `place=*` nodes with population for label priority.

### 2.3 Geocoding discipline (`build/geocode.js`)
Nominatim with a descriptive `User-Agent`, `sleep(1150)` between calls (policy: ≤1 req/s), 4 s backoff on 429, results rejected unless within 12 km of the claimed city, company bound to a building only if within 75 m of a footprint. Reuse this exact discipline for placing NPC homes/businesses.

### 2.4 Renderer notes (`app/render.js`)
Perspective camera at 27° FOV with explicit basis vectors (`updateCamera`), near plane `max(20, dist×0.0008)`, ground polygons clipped against the near plane before projection (`pathPolyFill`), static frame cached and only animated layers (cars, aircraft, rain, neon) composited per frame (<0.4 ms). Stylised traffic (`drawCars`): ≤70 cars, 26/14 m/s, phase from wall-clock — "presence and scale, not a simulation". Good model for the in-game minimap/pause-map layer.

## 3. gta-sa-earth — world streaming, ambient life, timecyc weather, mission interpreter and auto-director

Repo root: `.../repos/gta-sa-earth`; one 956 KB `index.html` (minified esbuild bundle of three.js r16x + three-mesh-bvh + app), plus `README.md`. It loads the user's own GTA:SA game files in the browser (`data/script/main.scm`, `data/Paths/carrec.img`, `text/american.gxt`, `data/paths/nodes{0..63}.dat`, `tracks*.dat`, `timecyc`). **We must not reuse its data parsers**, but its *systems* are the best small-scale reference I have seen for mission playback on a city map. Byte offsets below are into `index.html`.

### 3.1 World streaming
- Grid `en=32` cells × `ao=200 m` (origin `Xh=-3200`): 6.4 km square. `St.detail=450 m` load radius, unload at `1.35×`, ~60 ready cells max with LRU (`zb()` ~byte 938k). Geometry is built in a Worker (`fi.postMessage({type:'radar'})`, `request({type:'vehicle',…})`) and attached as groups; per-cell lights arrays drive night lighting.
- Camera: `PerspectiveCamera(55, …, 1, 20000)`, `up = +Z`, OrbitControls with `maxPolarAngle = π/2−0.03`, `zoomToCursor`, damping 0.12, LEFT=pan / RIGHT=rotate; a pointer-locked "fly" mode (`Va()`, `qb()`), 40 m/s (160 shift, 8 ctrl).

### 3.2 Path graph → traffic / pedestrians / boats / aircraft (`Wr`, `Vs`, `Ma`, `qd` classes, byte ~4089 line)
- `Wr(files, vehicles?, filter)` builds a single graph `{pos: Float32Array(N×3), width[], level[], adj[][], grid: Map(100 m buckets), N}` from per-area node files; `nodes[0..nVeh)` are vehicle nodes, the rest pedestrian nodes; links resolved via `(file<<16 | nodeIndex)`.
- `Vs(G, x, y, r)` = all node indices within a 100 m-bucketed square.
- `Ma` (ambient agents, used for cars, peds and boats via `mode:'water'`): `spawn()` picks a random node within `radius` of the camera (skips `level===3` nodes 80 % of the time), a random neighbour as the segment target, a pool model, two colours; `update()` advances `t += speed·dt/segLen`, at the end picks a random *other* neighbour (never U-turns unless dead end), applies a lane offset perpendicular to the segment, despawns beyond `1.25×radius`, boats get a bob/roll/pitch sine. Instanced rendering via `Xr` (per-model `InstancedMesh` with `iCol1/iCol2` instance colour attributes, cap 32–48).
- `qd` aircraft: planes/helis spawn on a ring `R=2600 m` around the camera, ≤5 planes + ≤3 helis.
- Takeaway: a **node/edge graph with spatial buckets, random-walk agents, and instanced rendering** is enough for a dense ambient city on mobile. Intersections and signals are not modelled.

### 3.3 Day/night + weather = `timecyc` keyframes (`Xb`, `Yb` at byte ~941.9k)
- `Nt.timecyc[weatherId].rows[hourSlot]` (GTA's `timecyc.dat`: per weather × 8 hour slots: `skyTop, skyBot, sunCore, sunSz, dir, amb, ambObj, fogSt, farClp, water[4], postFx1/2 + alpha`). `Xb(hour)` finds the surrounding slots and lerps every field (`Wb`).
- `Yb(dt)`: clock advance (`minute += dt×30` when playing), `uHour`, day-night scalar `uDN` (1 for 21–05 h, ramps 19–21 and 05–07), sun direction `angle = (t−6)/14·π` → `(cos, −0.25, sin)` with a moon stand-in at night, directional colour scaled by `clamp(sunZ×3)`, ambient ×0.55/0.9, fog colour = `skyBot`, water colour, stars `max(0, uDN−0.3)`, night lights visible when `uDN>0.05`, **post colour filter** from `postFx` (`uFilter = 1 + (c/lum − 1)×0.35`), and camera-altitude-aware fog: `fogFar = max(farClp, camZ×5 + farClp)`, `fogNear = max(fogSt, fogFar×0.35)`. ~12 uniforms, zero post-processing passes beyond a colour multiply — **this is the mobile-cheap weather model**.

### 3.4 Mission system — "simulate once, record a timeline, scrub it"
- Entry `C_()` (line 4090): parses script, car recordings (`carrec`), GXT text, train tracks; collects voice-line durations; constructs the interpreter `_h` and calls `run(missionIndex, {start})`, logging `"${title}: ${result} after ${duration} s game time (${ms} ms)"` — i.e. the entire mission is simulated ahead of time.
- **Interpreter `_h` (byte 796,908)**: `resetWorld()` creates the player char, handles start at 100; `run()` loops `while t < maxTime (20 min) && threads not done`: `exec(thread)` for every awake thread (≤20,000 instructions/tick; `WAIT` yields with `wake = t + ms`), `stepWorld(Jd×timeScale)` fixed step, thread timers at locals 32/33, `snapshot()` every 33 ms of game time, optional `onFrame`. Threads (`gh`) have `ip, base, locals DataView, stack, logic, cond, not`. `op()` dispatches on the decoded instruction's *name* (`WAIT, GOTO, GOTO_IF_FALSE, GOSUB, RETURN, IF, TERMINATE_THIS_SCRIPT, MISSION_HAS_FINISHED, START_NEW_SCRIPT, CREATE_MISSION_TRAIN, …`) with a generic math/compare path (`= =# + - * / += @ > >= ==`) and GTA's IF-chain semantics (`logic 0 = single`, `1–8 = AND n`, `21–28 = OR n`). Unknown opcodes are counted in `this.unknown`.
- **World model inside the interpreter**: entities `{h, kind:'car'|'char'|'obj', model, x,y,z, heading, born, gone, health, track[], area}`; cars have basis vectors `(rx,ry,rz),(fx,fy,fz)`, velocity, `rec` (recording playback via `M_` sampler), `attach` (trailer/tow), `goto` steering (heading rate limit 75°/s, speed × `max(0.35, 1−|turn|/120) × min(1, 0.4+dist/25)`), `burn` timer → `explode()`; chars have `tasks` (`goto, gotoShoot, kill, driveby, shootCoord, enterCar, leaveCar, carDrive, …`), seats, `follower`, `shooting`; trains run on `tracks*.dat` splines with cruise/accel. Simple pairwise car "damage" when `<4.2 m` apart; `combat()` resolves fires.
- **Autoplayer** (`autoplayer()`): the player is driven by *goals* that the script implies — `LOCATE_*` opcodes call `setGoal({type:'loc', x,y,z, onFoot, inCar, stopped})` whenever the player is *not* yet in the zone; goals `enter` (get in a car) and `follow` (chase an entity, incl. `chaseTrain`). It finds the nearest friendly car within 120 m, routes with the A* `router` over the path graph (binary-heap A*, 400 k node cap, lane offset `2.4 + min(3, width/16)` m to the right), re-plans every 2.5 s when following, and nudges toward hostiles when idle >2.5 s. This is the trick that makes an *unmodified* mission script play itself.
- **Event timeline** (27 `ev()` types): `cam, explosion, death, clearPrints, animStop, widescreen, weather, voice, timescale, sparks, smash, recStop, recEnd, rec, print, pedDensity, passed, fireStart, fire, failed, fade, cutscene, control, clock, carDensity, area, anim`. `run()` returns `{duration, result, ents, events, specials, unknown}`.
- **Player `Mh` (byte ~860k)**: `prep()` converts tracks to `Float32Array` with strides `car 12 / char 10 / obj 5`, detects death keyframes, splits events into typed arrays (`fires, prints, voices, cams, wides, scales, areas, booms, sparkEv, smashes, density, fireStart, fades, skips`); `lastBefore(arr, t)` is a binary search; `subjectPose(t)` returns `{pos, fwd, right, speed, bike, onFoot, car|target}` for the player (in-car pose from `carPose`, on-foot heading from the current fire target); `chaser(t)` = nearest hostile car currently shooting within 45 m. UI: play/pause, scrub bar with chapter markers (`def.chapters[].at` are predicates over events, e.g. `o.type==='rec' && o.num===252`), hatched skip regions (interiors → title card), 0.5–2× speed, subtitles from `print` events (≤6 s), letterbox bars on `widescreen`, fades, `Space/C/←/→/Esc` keys.
- **Auto-director `Ah` (byte 852,790)**: shot vocab on foot `[shoulder, shoulder, wide, shoulder, heli]`, in vehicle `[chase, chase, flyby, flyby, side, front, heli, rearlow, enemy, chase]` (weights by repetition); deterministic hash `le(seed, k)` so scrubbing is reproducible; `enemy` only if a chaser exists; **clearance check**: raycast `+1 m → +30 m` above subject (`segmentHit`, BVH) — if `<12 m` (tunnel/under bridge) demote flyby/heli/side/front to chase or rearlow, heli needs ≥29 m; first 5 s forced `heli`; durations `flyby 3.8 s, front 3.2 s, else 4.2 + rand×2.6 s`; `flybySpot()` picks a fixed vantage from pedestrian path nodes 4–15 m away with height within 4 m and line-of-sight to the subject *now and 2 s in the future*, falling back to lateral offsets. Per-shot offsets: chase `−fwd×(8|5.4 bike|3.4 foot) + up×(3.2|2.1|1)`, look `+fwd×5 +up×0.8`; shoulder `−2.6 fwd +0.8 right +0.7 up`; rearlow; side `6.5 right`; front `fwd×(9−1.2t)`; wide `9 right −3 fwd +3 up`; heli orbit radius 28 m at 24 m + `lift` (+12 m each time the view is blocked, max 90). Smoothing `k = 1−exp(−dt×g)` with `g` 2–9 per shot (forward vector smoothed at 3/5). **Camera collision**: if the ray from subject to camera is blocked, try 6 alternate offsets (mirror across right, pull-in high, top-down, front-left/right, overhead) and lerp toward the best; `watch()` samples every 0.2 s and cuts to a new shot after 0.8 s of occlusion. `applyShake()` decays `exp(−3dt)` for explosions. Script cutscene cameras (`cams` events, `mode fixed`) override when "Cutscene cams" is on.

## 6. Pattern cards

**P1 — Single local ENU frame + flat-earth metres** · San-Francisco `src/world/coords.ts` · One origin (City Hall), `+X E / +Y up / −Z N`, per-degree constants; ECEF only for the sky. · Apply: define `world/coords.ts` identically for Dee-Verse; physics (Rapier/wasm), nav, roads, mission waypoints all in ENU metres; store authored content in lat/lon and convert at bake. · Caveat: 80 km extent is fine; beyond ~150 km the projection error exceeds a lane width.

**P2 — Offline bake to static binary chunks, zero runtime API keys** · San-Francisco `tools/*.ts`, `GATES.md` G1 · All geo data fetched by Node scripts into `.context/`, written as quantized binaries + manifest under `public/data/`. · Apply: `tools/bake-*.ts` → `public/world/{terrain,buildings,roads,landuse,labels}`; serve from Cloudflare Pages/R2 with immutable cache headers; PWA can precache the core cells. · Caveat: Overpass fair-use (<10 k queries/day, no parallel scripts); prefer one Geofabrik `norcal` PBF + `osmium extract` for the Bay Area.

**P3 — Int16-quantized per-cell building format** · San-Francisco `tools/buildings.ts` L354–391; Atlas `build_scene.js` Packer · 8-byte header + 4 bytes/vertex at 8 cm (SF) / 25 cm (Atlas). · Apply: add `u8 styleClass` (Victorian/Marina/SOMA-glass/warehouse/parody-landmark) and `u8 districtId`; keep 2.5 km cells for SF core, 5 km for the far Bay. · Caveat: cell boundaries cut footprints; assign by centroid (both repos do).

**P4 — Worker-meshed, priority-streamed, frame-budgeted cells** · San-Francisco `src/world/BuildingsLayer.ts` · Direction-weighted priority, 2 concurrent fetches, ≤1 GPU upload/frame, 8-frame cull cadence, 2.8 km always-on radius, behind-camera cull. · Apply: same for buildings, roads, props; extend priority with vehicle speed (look-ahead distance `v × 4 s`). · Caveat: upload budget assumes ~100 k-tri cells; split larger cells.

**P5 — Shared heightfield sampler for bake and runtime** · San-Francisco `tools/terrain.ts BakedTerrainSampler` + `TerrainAndWater.sampleGroundHeight` · Same bilinear sampler in Node and browser; roads draped at bake (≤20 m subdivision), everything anchored to the DEM. · Apply: use for road draping, prop placement, vehicle suspension ray fallback, camera ground clamp; also bake "bridge corridor" overrides (`gradeBridgeCorridors`) so GGB/Bay Bridge decks never intersect terrain. · Caveat: 39 m grid is too coarse for driving — bake z15/z16 Terrarium (≈3.8/1.9 m) for the 20 km core.

**P6 — Road class table → ribbon meshes + lane offsets + spawn routes** · San-Francisco `tools/roads.ts`, `RoadsAndLanduseLayer.buildRibbonGeo/buildMovingCityTraffic`; Atlas `mergeWays` · Map OSM `highway=*` to 9 classes with widths; merge fragments into strokes; ribbons with casing/fill/centre line; traffic lanes at `width×0.23`. · Apply: this is the *visual* road layer; for drivable AI build a proper graph (P7). · Caveat: neither repo models intersections, one-way, turn restrictions or signals.

**P7 — Node/edge path graph with 100 m buckets, random-walk ambient agents, A* for goals** · gta-sa-earth `Wr`, `Vs`, `Ma`, `P_` (router), `autoplayer` · Graph `{pos, width, adj, grid}`; agents pick random next edge (no U-turn), lane offset, despawn beyond 1.25× radius; A* with binary heap and lane-offset path. · Apply: build the graph at bake from OSM ways (split at shared nodes, respect `oneway`, `lanes`, `maxspeed`, `turn:lanes` where present) into `roads/graph.bin`; use random-walk for ambient traffic/peds, A* for police/mission vehicles; separate ped graph from sidewalks/`footway`. · Caveat: GTA's node files already encode lanes/levels; from OSM we must derive `width` (lanes×3.3 m) and bridge/tunnel `level` from `layer`.

**P8 — Instanced ambient life with per-instance colour attributes** · gta-sa-earth `Xr`; San-Francisco traffic (4 InstancedMeshes for 540 cars) and trees (47,896 in 5 meshes) · Apply: one `InstancedMesh` per vehicle/ped archetype, caps 32–48 per model, colour via instance attributes; cars as 2-box LOD beyond 150 m. · Caveat: `frustumCulled=false` + manual distance throttling is required or the whole batch pops.

**P9 — Takram physical sky + volumetric clouds + N8AO post stack (desktop tier)** · San-Francisco `src/world/atmosphere.ts`, `environment.ts` · ECEF basis from origin; GPU-precomputed LUTs (or `?bakedLUT` loader); clouds at 0.6 resolution scale, 2 shadow cascades; PMREM env re-bake gated by sun movement; auto-exposure. · Apply: desktop/"Ultra" tier only; expose presets `day/golden/fog/night` and drive `night/dark/warmth` scalars into every material. · Caveat: shader string-patching of takram internals (`localWeather` mask, `cloudAmbient`) breaks on upgrade; takram last released 2026-05-06 and its WebGL path is scheduled for archival; `requestIdleCallback` starvation must be polyfilled with a timeout; LUT precompute can trip GPU watchdogs in headless CI.

**P10 — `timecyc`-style keyframed weather for mobile** · gta-sa-earth `Xb/Yb` · Per-weather × per-hour rows → lerp → ~12 uniforms (sky top/bottom, sun colour/size/dir, ambient, fog near/far/colour, water, post colour filter, stars, lights-on). No post passes. · Apply: author `weather/timecyc.json` for `clear, karl-fog, overcast, rain, smoke, golden`, 8 hour slots; a sky dome shader with gradient + sun disc + stars; `scene.fog` analytic; one colour-grade multiply. This is the default tier for iPhone/Quest. · Caveat: no aerial perspective or cloud shadows; pair with P9 on desktop via the same preset names.

**P11 — Analytic height fog in one post effect** · San-Francisco `src/world/fog.ts` · 20-line depth-based exponential height fog (`uDensity, uHeight, uGround, uColor`). · Apply: Karl-the-Fog marine layer sliding over the Sunset/Richmond at a fixed height. · Caveat: needs a depth texture; on WebGPU use a TSL `fogNode` instead.

**P12 — Adaptive quality governor + pixel budget + altitude-scaled near plane** · San-Francisco `main.ts` · EMA frame time → one-way tier drop; DPR from a 2.56 M px budget; `near = clamp(clearance×0.14, 2, 22)`. · Apply: tiers `ultra/high/balanced/mobile`; on mobile start at budget 1.2 M px and DPR ≤1.25. · Caveat: make the governor two-way with hysteresis for long sessions.

**P13 — Simulate-once mission timeline + scrubbable player** · gta-sa-earth `_h.run`, `Mh.prep`, `lastBefore` · Deterministic fixed-step simulation of the scripted mission records entity tracks (33 ms snapshots) and typed events; playback scrubs with binary search; chapters are predicates on events; interior scenes become title cards. · Apply: use this for **cutscene/replay/preview** of a mission (and for generating the MiniMax cutscene storyboard: feed camera + subject tracks to the video model prompt), and for the mod forum's "watch this mission" previews; live gameplay still runs the same script interactively. · Caveat: requires determinism (seeded RNG, fixed dt); physics engines must be stepped identically.

**P14 — Goal-driven autoplayer from script zone checks** · gta-sa-earth `locate()` → `setGoal`, `autoplayer()` · Zone-test opcodes that fail set a goal; the autoplayer drives to it (nearest friendly car, A* route, re-plan every 2.5 s). · Apply: implement `mission.autoplay()` for QA (every mission must be completable by the bot in CI), for attract-mode demos, and for "skip this part". · Caveat: needs a navmesh/graph for on-foot too (gta-sa-earth moves on-foot chars in straight lines).

**P15 — Cinematic auto-director with shot vocabulary, LOS validation and occlusion-triggered cuts** · gta-sa-earth `Ah` · Weighted shot lists by context (on-foot vs vehicle), deterministic seeds, clearance raycasts above subject, `flybySpot` from path nodes with LOS to present and +2 s future pose, per-shot offsets and damping constants, 6-candidate collision fallback, heli lift when blocked, cut after 0.8 s occluded, explosion shake. · Apply: port as `camera/Director.ts` (TypeScript, three-mesh-bvh for `segmentHit`); reuse for Culture Wars intros/finishers, Racing replays, mission cutscenes; expose `force` shot for authored moments. · Caveat: tune constants for SF hills (clearance checks are vertical — add a slope-aware variant); OrbitControls must be disabled while directing.

**P16 — Coastline ring assembly and region-scale LOD** · Atlas `build/geo.js assembleLand`, `build_scene.js` · Land polygons from directed coastline ways clipped and closed on the rectangle; buildings only in cores, streets elsewhere; per-class DP tolerances; 1 km cells. · Apply: the "far Bay" (Oakland, Berkeley, Peninsula, San Jose) as flat-shaded massing + arterials, loaded as one ~3 MB pack; SF core at full detail. · Caveat: Atlas heights are ×1.55 exaggerated for relief-model look — don't carry that into the playable layer.

**P17 — Stylised 2D map layer from the same dataset** · Atlas `app/render.js` (cached static frame + animated overlay; near-plane clipping of ground polygons) · Apply: pause-map and minimap in Canvas 2D/WebGL from `roads/graph.bin` + land/water packs, or PMTiles via Protomaps on R2; cache the static frame per zoom. · Caveat: keep it in the same ENU frame as gameplay to avoid a second projection.

**P18 — CI gates for a 3D web world** · San-Francisco `GATES.md`, `scripts/verify-*.mjs`, `deploy.yml` · No-keys scan, baked-data counts, type-check + build, screenshot luminance assertions. · Apply: add `verify-world-counts`, `verify-no-keys`, `verify-screens` (Playwright headless, `?bakedLUT`, `?weather=fog&hour=7`), plus `verify-missions-autoplay` (P14). · Caveat: headless GPU LUT precompute → use baked LUTs in CI.

## 7. Recommendations for the spec

1. Adopt the San-Francisco repo's **open-data-only world** as the canonical gameplay geometry: DataSF `ynuv-fyni` (PDDL) for SF buildings, OSM (ODbL) for roads/rail/parks/water/coastline/Bay-Area buildings, AWS Terrarium DEM (public domain), USGS imagery for colour sampling. Record attributions in `CREDITS.md` and the pause menu: "© OpenStreetMap contributors (ODbL)", "Building footprints: City and County of San Francisco (PDDL)", "Elevation: 3DEP data courtesy of the U.S. Geological Survey / Terrain Tiles (Mapzen)".
2. Exclude Google Photorealistic 3D Tiles and Mapbox tiles from v1. If a "photo mode" is ever added, isolate it in `src/photo/` behind an online-only flag using `3d-tiles-renderer@0.5.x`, keep the Google logo + provider attribution on screen, never raycast or bake against those tiles, and budget $6 / 1,000 root-tile requests after 1,000 free per month.
3. Define `world/coords.ts` exactly as in the SF repo (ENU, City Hall origin, `+X E/+Y up/−Z N`); add `FAR_BOUNDS` 80 km and a Bay-Area "region" tier from the Atlas pipeline (flat massing + arterials, ~3 MB).
4. Bake terrain at Terrarium z15 for the 20 km core (≈3.8 m) and z12 for the 80 km far field; keep one `BakedTerrainSampler` shared by Node bake and browser runtime; bake bridge-corridor grading for Golden Gate and Bay Bridge.
5. Build a **drivable graph** at bake time (`roads/graph.bin`): split OSM ways at shared nodes, honour `oneway`, `lanes` (default by class), `maxspeed`, `layer/bridge/tunnel`, `turn:lanes`; store `{pos, width, level, adj, grid100m}` as in gta-sa-earth; separate pedestrian graph from `footway/sidewalk`; emit intersection nodes with simple signal timing. Keep the SF repo's ribbon mesher for visuals.
6. Ambient life = random-walk instanced agents on the graph (cars ≤540 instances in ≤4 draw calls per archetype, peds, boats on a water graph, aircraft on a 2.6 km ring); police chases and mission vehicles = A* with re-plan every 2.5 s and `goto` steering limits (75°/s heading rate, speed × turn factor).
7. Weather/time: ship a `timecyc.json` keyframe model (P10) as the base tier for all platforms; layer takram atmosphere + clouds + N8AO (P9) only on `ultra` desktop. Both read the same preset names (`day, golden, fog, night, rain, overcast`) and emit the same shared uniforms (`uNight, uDark, uSunDir, uSunColor, uFogColor/Near/Far`).

## 8. Risks

- **ODbL share-alike scope**: our baked world files are a derivative database; publishing the game "publicly uses" it, so we must offer the derived DB (or bake scripts) under ODbL. Fine for an open repo; a problem only if the owner later wants proprietary world data mixed into the same database.
- **Google 3D Tiles are incompatible with a cached/offline PWA and with collision/nav derivation**; using them for gameplay would violate the Map Tiles API Policies. Full ToS text could not be fetched (JS-rendered page).
- **takram maintenance**: last release 2026-05-06; README states API may change without backward compatibility; WebGL path slated for archival; the SF repo string-patches takram shaders. Isolate behind an adapter and keep the `timecyc` tier as the fallback sky.
- **Overpass dependence**: public instances are overloaded and rate-limited; `kumi.systems` endpoint used by the SF repo no longer exists. Bake from Geofabrik PBFs.
- **DEM resolution**: the SF repo's 39 m grid produces unrealistic road grades; z15/z16 Terrarium increases bake size (~4–16× the DEM). Coastline/bathymetry noise needs the same clamping trick.
- **Determinism** for simulate-once missions requires seeded RNG and a fixed physics step; mixing a WASM physics engine with variable dt breaks scrubbing.
- **Overture transportation drivability is unverified**; evaluate before replacing the OSM-derived graph.
- **NAIP imagery licence** (public domain) and the exact `GoogleCloudAuthPlugin` import path are UNVERIFIED.
- gta-sa-earth's systems are tied to Rockstar file formats; only the architecture may be reused (brief forbids Rockstar assets/data/code).
